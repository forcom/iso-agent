# 에이아이듀 주식회사 회사소개서

> **문서 목적**: 본 문서는 가상의 AI 교육 스타트업 "에이아이듀 주식회사"의 개요를 정리한 것으로, ISO/IEC 42001(AI 경영시스템) 매뉴얼·절차서·지침서 작성 시 **조직 상황(4항), 리더십 및 역할(5항), 지원(7항), 운영(8항)** 검토의 기초 자료로 사용한다.
>
> **출처 표기**
> - **[설정]**: 회사 설정값(요청자 제공)
> - **[영향평가서]**: 첨부 「Edu Score (AI기반 학생 평가 서비스)」 영향평가 예시
> - **[확인 필요]**: 아직 정해지지 않은 사항 (임의로 채우지 않음, 10장에 모아 정리)
>
> ※ 본 회사와 서비스는 가상으로 설정된 것이며 실제 존재하는 기업·서비스를 지칭하지 않는다.

## 4. 역할과 책임

### 4.1 AI 경영시스템(AIMS) 역할 [설정]

| AIMS 역할 | 담당 | 비고 |
|---|---|---|
| AIMS 책임자 | CTO | 기술·보안·AI 책임 임원 겸임 |
| 내부심사원 | 회계팀(경영지원), DevOps Engineer(기술) | 심사원 풀은 전 직원. 필요 시 심사원 교육 수행 |
| AI 영향평가 담당 | Privacy & AI Safety Engineer | 운영팀 소속 |
| 문서관리·교육 | 총무팀 | |
| 공급자 계약 | 회계팀 | |
| 고객 대응 | 영업팀 | |

### 4.2 직무 분리 [설정]

- AI 시스템의 **개발과 검증·승인은 모두 CTO가 수행**한다.
- 단, **개발 단계에는 개발/AI팀 전원**, **검증 단계에는 운영팀 전원**이 참여(참조)한다.
- 조직 규모상 개발과 승인 권한이 CTO 1인에게 모여 있으므로, 매뉴얼에서는 팀 단위 참여 기록(개발 = 개발/AI팀, 검증 = 운영팀)을 남기는 방식으로 이를 보완하는 것이 자연스럽다.
- 내부심사원은 자신의 업무를 심사하지 않도록 배정해야 한다(42001 9.2 객관성·공정성). 회계팀 심사원은 공급자 계약을, DevOps Engineer는 인프라 운영·배포를 심사하지 않도록 교차 배정한다. 예: DevOps Engineer가 경영지원 영역(공급자 관리 포함)을, 회계팀이 기술 영역을 심사.

### 4.3 직무별 역할

| 직무 | 설정된 역할 [설정] | AI 경영시스템 관련 영역 |
|---|---|---|
| CEO | 대표 | 최고경영자로서 AI 정책 승인, 자원 제공, 경영검토 (42001 5항) |
| COO/CFO | 경영 및 기획 책임 임원 | 경영 기획, 예산·자원, 경영지원 조직 관리 |
| 총무팀 | 총무 업무 | AIMS 문서관리, 교육 운영 |
| 회계팀 | 회계, 세무, 경리 | 공급자 계약, 내부심사원 |
| 영업팀 | 영업 및 마케팅 | 고객 대응 |
| CTO | 기술 및 보안, AI 책임 임원 / 개발/AI팀·운영팀 팀장 겸임 | AIMS 책임자, AI 시스템 개발·검증·승인 |
| Backend Engineer | 백엔드 개발 | 서비스 기능 개발, 데이터 처리 로직 |
| Frontend Engineer | 웹 프론트엔드 개발 | 이용자 화면(평가 결과·피드백·리포트 표시) |
| Designer | 프로덕트 및 홈페이지 디자인 | 이용자에게 AI 결과를 전달하는 화면 설계 |
| AI Engineer | AI 모델 연구, 개발 | 외부 AI 모델(OpenAI·Gemini)을 활용한 평가 기능 연구·개발 |
| AI Software Engineer | AI 모델 서빙 개발 | 외부 AI API 연동 및 서빙 |
| Data Engineer | 학습용 및 운영 데이터 수집·처리·분석 | AI 시스템용 데이터 관리, 외부 API 전송 전 가명처리 담당 (42001 부속서 A.7) |
| DevOps Engineer | 프로덕트 운영 (세부 설명 없음) | 인프라(AWS) 운영, 배포·모니터링, 내부심사원 |
| Security Engineer | 프로덕트 운영 (세부 설명 없음) | 정보보호 |
| Privacy & AI Safety Engineer | 프로덕트 운영 (세부 설명 없음) | AI 영향평가 담당, 개인정보보호, AI 안전성 |

> 개발/AI팀 전원은 개발 단계, 운영팀 전원은 검증 단계에 참여한다.

## 5. 대표 서비스: Edu Score

### 5.1 서비스 개요 [설정 · 영향평가서]

- 학생이 제출한 시험 답안·과제·에세이 등 학습 데이터를 수집·분석하여 **평가 점수를 산출하고 제한적 피드백을 제공**하는 AI 기반 학생 평가 서비스
- 학생이 제출한 **객관식·단답형·서술형 답안 및 에세이 과제**를 분석하여 점수를 산출하고, 필요 시 학습 역량 향상을 위한 제한적 피드백 제공. **서술형·에세이 평가에도 AI를 적용**한다
- **AI 작성 확률 판별 기능**을 포함한다 (제출물이 AI로 작성되었을 확률 산출)

### 5.2 목적 및 필요성 [영향평가서]

- **목적**: 교사·교수의 교육 활동을 보조하여, 학습자에게 보다 질 높은 교육을 제공할 수 있도록 지원
- **필요성**: 평가의 일정 영역을 시스템이 담당하게 함으로써 교사는 종합적 평가와 피드백 제공에, 학생은 역량 성장에 집중할 수 있도록 도움

### 5.3 적용 분야

서비스 대상 학습자는 **성인(대학생 및 직장인 등)**이다. 영향평가서의 적용 분야 중 초·중·고는 현재 대상이 아니다.

| 영향평가서상 적용 분야 | 현재 적용 현황 |
|---|---|
| 초·중·고·대학 등 교육기관의 정규·보충 수업 과정 | 대학 5개 (초·중·고는 대상 아님) |
| 온라인 학습 플랫폼 | 민간 온라인 교육 서비스(LMS) 10개 (직장인 등 성인 학습자) |
| 개별 학습자의 자율 학습 진단과 피드백 | 해당 없음 (개인 구독 없음) |

### 5.4 사용 절차 [영향평가서]

1. 교육기관이 서비스에 가입하고 평가 기준을 등록
2. 학생이 과제·답안을 제출하면 시스템이 자동으로 데이터를 분석 ← **AI 작동**
3. AI 모델이 점수와 피드백(및 AI 작성 확률)을 생성 ← **AI 작동**
4. 교사·교수와 학생이 결과를 확인하고 학습 계획에 반영
5. 평가 종료 후 1개월간 이의제기에 대비해 데이터를 보관한 뒤 삭제

### 5.5 운영 기간 및 빈도 [영향평가서]

- 운영 기간: 학기·학년도 단위로 상시 운영
- 빈도: 평가 시점이나 과제 제출 시마다 반복 사용

### 5.6 이용자 및 이용 규모

| 구분 | 내용 | 규모 [설정] |
|---|---|---|
| 고객사 | 대학, 민간 온라인 교육 서비스(LMS) | 대학 5개, LMS 10개 |
| 직접 이용자 – 교육기관 담당자 | 서비스 도입 결정, 평가 기준 등록 [영향평가서] | 설정에 없음 |
| 직접 이용자 – 교수자 (교사·강사·교수) | 기본적인 시스템 사용 역량은 있으나 AI 모델 작동 원리에 대한 전문 이해는 제한적일 수 있음 [영향평가서] | 100여 명 |
| 직접 이용자 – 학생 | 성인(대학생 및 직장인 등). 과제·답안 제출, 결과·피드백 확인 | 5,000여 명 |

### 5.7 이용자 선택권 [영향평가서]

- 교육기관이 서비스 도입 여부를 결정
- 기관 도입 이후에도 개별 교사·교수는 서비스 활용 여부를 선택 가능
- 개인 구독은 운영하지 않으므로, 영향평가서의 "개인 학습자의 직접 구독 선택"은 해당 없음

### 5.8 AI 시스템 구성 [설정]

| 구성 요소 | 현황 |
|---|---|
| AI 모델 | 외부 AI API만 사용: OpenAI API, Gemini API 모두 Edu Score 서비스에 사용 |
| 자체 모델 | 없음 (자체 학습·파인튜닝 모델을 운영하지 않음) |
| 모델 간 역할 분담 | 본 문서에서는 정하지 않음. AI 시스템 목록·설계 문서 작성 시 기능별로 기재 |
| 모델 서빙 | AI Software Engineer 담당 |
| 데이터 처리 | 학습용 및 운영 데이터 수집·처리·분석 (Data Engineer 담당) |
| 외부 API 전송 데이터 | 학생 개인 학습 정보는 전처리 단계에서 **가명처리 후** 외부 API로 전송. 가명처리는 Data Engineer 담당 |
| 인프라 | AWS 서울 리전 |

### 5.9 데이터 관리 [설정]

| 항목 | 내용 |
|---|---|
| 처리 데이터 | 학생 답안·과제·에세이·성적 등 개인 학습 정보 [영향평가서] |
| 외부 API 전송 | 가명처리 후 전송 (Data Engineer 담당) |
| 외부 공급자 보관·학습 활용 | 불가 (공급자 측 데이터 보관 불가, 학습 활용 불가) |
| 보관 기간 | 평가 종료 후 1개월 (이의제기 대응 목적) 경과 시 삭제 |
| 저장 위치 | AWS 서울 리전 |
| 접근·보호 | 권한 있는 사용자만 접근, 저장·전송 시 암호화 [영향평가서] |

## 8. AI 위험 및 현재 관리 방안 [영향평가서]

### 8.1 위험 시나리오 (시나리오 1)

한 대학 미디어커뮤니케이션학과 학생 B의 에세이를 AI가 분석한 결과, AI 작성 확률이 40~70%로 산출되고 평가 점수는 C+로 부여됨 → 담당 교수 C가 이를 그대로 성적에 반영 → 학생 B가 직접 작성한 과제라며 정정 요구 → 교수가 AI 판별의 한계를 고려해 재평가하여 B로 수정 → 학생 B는 수정 결과도 초기 AI 점수의 영향(닻내림 효과)을 받았다며 학교 당국에 이의 제기

### 8.2 기본권 영향 및 관리 방안

| 관련 기본권 | 영향 내용 | 영향 규모 | 영향 기간 | 발생 가능성 | 이행 중인 관리 방안 |
|---|---|---|---|---|---|
| 평등권 | 특정 문체·언어 패턴 편향 시 일부 학생 불리, 공정성 논란 시 평가 신뢰도 저하 | 높음 | 중기 | 높음 | 중요 과제는 교사 표본 검토로 교차 확인 / 객관식·단답형 채점 등에만 제한적으로 AI 활용 |
| 알권리 | 설명가능성 한계로 납득할 근거 제시 어려움, 결과 개선 기회 제한 | 높음 | 단기 | 매우 높음 | 평가 근거·결과 리포트 제공 / 성적 이의제기 및 재검토 절차 운영 |
| 사생활의 비밀 | 과제·답안·성적 등 개인 학습 정보의 저장·분석·유출 우려, 미삭제 시 학습 이력 과도 축적 | 높음 | 장기 | 중간 | 학습 데이터 최소 수집 및 평가 종료 후 자동 삭제 / 권한 있는 사용자만 접근, 저장·전송 시 암호화 |

> 영향평가서 원문은 "⋮"로 추가 시나리오·기본권 항목이 있음을 표시하고 있어, 위 표는 전체가 아닐 수 있다.

### 8.3 설정 사항 반영 시 영향평가서 갱신 필요 사항

설정 사항과 기존 영향평가서 사이에 다음 차이가 있어, AI 영향평가 담당(Privacy & AI Safety Engineer)이 영향평가를 갱신할 때 반영해야 한다.

| 항목 | 기존 영향평가서 | 설정 사항 | 갱신 방향 |
|---|---|---|---|
| AI 적용 범위 (평등권 관리 방안) | 객관식·단답형 채점 등에만 제한적으로 AI 활용 | 서술형·에세이 평가에도 AI 적용 | 해당 관리 방안 삭제 또는 서술형·에세이에 맞는 대체 통제로 교체 |
| 데이터 삭제 (사생활의 비밀 관리 방안) | 평가 종료 후 자동 삭제 | 평가 종료 1개월 후 삭제 (이의제기 대응) | 보관 기간을 1개월로 명시 |
| 외부 API 전송 | 언급 없음 | 가명처리 후 전송, 공급자 보관·학습 활용 불가 | 사생활의 비밀 관리 방안에 추가 |
| AI 작성 확률 판별 | 시나리오에만 등장 | 서비스 기능으로 포함 | 판별 오류(오탐) 위험을 별도 위험 항목으로 평가 |
| 적용 대상 | 초·중·고·대학 | 성인(대학생·직장인 등) | 피영향자 범위와 학부모·교육청 관련성 재검토 |
| 이용자 선택권 | 개인 학습자의 직접 구독 선택 가능 | 개인 구독 없음 | 개인 구독 관련 내용 삭제 |
