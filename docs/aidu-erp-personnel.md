# 에이아이듀 ERP 직원·기능상 역할 로컬 설정

설정 ID: `aidu-personnel-2026-10-23`  
작성일: 2026-10-23  
관련 구현 기준: [Issue #2](https://github.com/forcom/iso-agent/issues/2)

## 1. 목적과 적용 범위

사용자의 2026-10-23 요청에 따라 [회사소개서](aidu-company-profile.md)의 조직도와 [15명 페르소나](aidu-personas.md)를 ERP의 직원·기능상 역할에 연결한다. **회사·서비스·인물과 이 배정은 가상 회사의 로컬 운영 설정**이다. 실제 인사발령, 실제 승인자의 서명, 접근권한 승인, 심사원 적격성 확인 또는 법정 담당자 지정을 입증하지 않는다.

이 설정은 기존 직원·역할이 없는 로컬 환경에 최초 지정을 추가하기 위한 명시적 입력이다. 빈 역할 지정서에 승인 결과를 합성하거나 페르소나를 실제 승인 기록으로 바꾸지 않는다. 로컬 적용 사건에는 가상 설정과 사용자 요청에 따른 적용임을 남긴다. 실제 배포 준비의 승인 증거를 대신하지 않는다.

입력 파일은 [`apps/seed/inputs/aidu-personnel.json`](../apps/seed/inputs/aidu-personnel.json)이다. 원문 근거와 설정 문서의 해시를 함께 보존하여 어느 설정으로 직원·역할을 추가했는지 확인한다. 원본 회사소개서와 페르소나는 수정하지 않는다.

입력의 `authorizedAt`은 `2026-10-23T00:00:00+09:00`으로 둔 **로컬 적용 기준일**이다. 사용자 요청이 발생한 정확한 시각이나 회사 승인자의 서명 시각을 뜻하지 않는다. 실제 적용 시각은 별도 설치 사건에서 기록한다. 종료일·과거 인사발령일·대리 승인자를 추정하여 만들지 않는다.

## 2. 조직 및 권한 범위

- 인원은 경영진 3명, 경영지원 3명, 개발/AI팀 6명, 운영팀 3명으로 총 15명이다. CTO의 개발/AI팀장·운영팀장 겸직은 별도 인원으로 세지 않는다.
- 기존 지식 릴리스의 20개 기능상 역할을 사용한다. 부서·직함·인명 문자열만으로 새 권한을 만들지 않는다.
- 모든 직원에게 `업무 수행자`를 전사 범위로 부여한다. 나머지는 아래 표에 명시한 역할만 부여한다.
- `전사`는 해당 기능상 역할의 전사 업무 범위(`all`)다. 모든 기능상 역할이나 모든 행위를 허용하는 관리자 와일드카드가 아니다.
- `Edu Score`는 이미 등록된 평가 대상 시스템 하나의 범위(`system`)다. 신규 시스템·인프라·데이터 자원 엔터티를 추정하여 추가하지 않는다. 이 범위의 역할을 쓰는 기록에는 Edu Score를 지정해야 하며, 시스템이 지정되지 않은 전사 기록에는 해당 역할의 권한이 적용되지 않는다.
- 현재 부서별 접근 범위는 구현되어 있지 않다. 보고 체계와 담당 부서는 표시·업무 배정 정보이며 부서 격리가 강제된다고 주장하지 않는다. 시스템 범위와 기록별 `auditedPersonIds`·`implementerIds` 등 구현된 조건으로만 제한한다.
- 로컬 ERP 운영자 자격은 문서·기록관리 담당자 **P04 홍길순 한 명**에게 부여한다. 운영자 화면 접근 자격과 규정별 작성·검토·승인·역할 지정 적용 권한은 별도다. 기술 검토와 대표 승인 권한을 운영자에게 이전하지 않는다.

## 4. 이번 설정에서 정한 기능상 배정

다음 항목은 인물의 직무를 현재 ERP 역할 체계에 연결한 **이번 로컬 배정 판단**이다. 원문에 이미 존재하는 인사발령으로 표현하지 않는다.

| 배정 | 설정 이유 | 권한 경계 |
|---|---|---|
| 윤승용 → 계약 승인권자 | CEO의 경영 의사결정 책임에 연결하고, 원문에 없는 COO 전결·대리 위임을 만들지 않기 위함 | 금액별·계약 종류별 전결 규칙은 추가하지 않음. 기술 수행 가능성 확인을 대체하지 않음 |
| 김철수 → 리스크·조치 책임자 | 기술·운영·AIMS 총괄 직무를 Edu Score 조치 총괄에 연결 | 모든 조치를 직접 구현했다는 뜻이 아니며 개별 조치 담당·검증자를 실제 기록에 지정 |
| 홍길순 → 심사 운영 담당자 | 페르소나 287행의 심사 일정·자료 안내를 기능상 역할로 연결 | 심사원 적격성이나 전 영역 심사 권한은 부여하지 않음 |
| 최운영 → 자원 책임자 | AWS 인프라 운영·배포·모니터링 직무를 Edu Score 자원 관리에 연결 | 전사 예산·계약 승인권이나 모든 자원 관리권을 부여하지 않음 |
| 장현우 → 독립 검증자 | 정보보호 검증 업무를 Edu Score 시정조치의 검증 참여에 연결 | 구현·조치에 관여한 건에서는 독립 검증할 수 없음 |

김철수의 `시스템 책임자`는 Edu Score의 개발·검증·승인과 두 팀장 겸직에서 연결했다. 정서진·김철수·윤승용의 `업무 책임자`는 조직 관리·보고 체계에서 연결했다. 이 역할만으로 부서별 격리가 구현되거나 실제 역량 평가가 완료되었다는 뜻은 아니다.

홍길동의 `인공지능안전관리자`는 안전 실무 조정에 연결한다. 총무·회계·영업·개발·운영의 다른 기능상 역할을 홍길동 한 사람에게 넘기지 않으며 AIMS 책임자는 CTO라는 원문 설정을 유지한다.

## 5. 직무 분리와 독립성

1. 회사소개서는 CTO가 개발·검증·승인을 수행하고 개발/AI팀 전원이 개발에, 운영팀 전원이 검증에 참여하도록 정한다. 이를 역할명만 바꾸어 다른 조직 구조로 만들지 않는다. 참여 결과·이견과 CTO 관련 중대한 이해충돌의 CEO 상향 검토가 필요하다.
2. 김영희는 자신이 관리한 공급자 계약을, 최운영은 자신이 수행한 인프라 운영·배포를 내부심사하지 않는다. 심사별 피심사자·이해충돌 정보를 확인해야 한다. 실제 심사원 적격성·독립성 확인 기록은 별도로 작성한다.
3. 장현우가 구현·조치에 관여한 건은 장현우가 독립 검증하지 않는다. 기록의 구현자 목록을 정확히 남기고 다른 적격 검증자를 지정한다. 역할 보유만으로 독립성이 입증되지 않는다.
4. 업무 수행자 전원에게 내부심사원 권한을 부여하지 않는다. 회사소개서의 “전 직원 심사원 풀”과 실제 기본 심사원 두 명의 역할 지정을 구분한다.
5. 인물의 경력 연수·대표 발언·가상 산출물은 실제 역량 증거·평가 결과·운영 실적으로 가져오지 않는다.
