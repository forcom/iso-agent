# 1 목적

### 1.1 이 지침서는 매뉴얼과 절차서에서 정한 인공지능경영 활동을 수행할 때 사용하는 자료 수집, 양식 작성, 평가 근거 정리, 검토 요청 및 후속 확인의 실무 방법을 정한다.

### 1.2 담당자는 이 지침의 작업 방법을 해당 업무에 적용하되, 승인권자·의무·정기 주기·리스크 수용 기준은 상위 절차서를 따른다. 실제 수행 결과와 승인·방침·평가서는 별도 기록으로 관리한다.

# 2 적용범위와 사용 방법

### 2.1 회사의 신규·변경 AI 서비스와 내부 AI 사용, 연간 AIMS 운영, 사건·불만 및 개선 업무에 적용한다. 시스템의 구현·시험·배포·데이터 삭제 작업은 [시스템 수명 주기 및 데이터 관리지침서](AIDU-AIG-08-02.md)를 함께 사용한다.

### 2.2 업무를 시작할 때에는 다음 순서로 필요한 작업과 기록을 선택한다.

1) 신규 도입, 계획된 변경, 정기 검토, 사건·불만 또는 종료 중 개시 사유를 확인한다.
2) 대상 시스템·버전·고객 사용 범위를 확인하고 기존 기록을 검색한다.
3) 기존 기록의 전제가 유효하면 해당 기록에 변경분·검토일·근거를 연결한다. 대상이나 전제가 다르면 새 평가를 수행한다.
4) 하나의 업무 기록으로 여러 양식을 충족하는 경우 양식 ID와 대응 구역을 표시한다. 동일한 설명·첨부를 문서마다 복제하지 않고 유효한 원본을 연결한다.
5) 필수 판단·승인 근거가 없으면 해당 항목을 미확정으로 관리한다. 해당하지 않는 심층 항목은 상위 절차의 비례 적용 원칙에 따라 사유를 간략히 표시하거나 생략한다.

### 2.3 상세 양식은 다음 조건에 따라 사용한다.

| 양식 | 사용 판단 |
| --- | --- |
| [법령 적용 판정 04-01-F05](../forms/AIDU-AIP-04-01-F05.md) | 시스템 도입과 주요 변경 시 법적 역할·적용성을 확인한다. |
| [리스크 범위·기준·협의 06-01-F06](../forms/AIDU-AIP-06-01-F06.md) | 공통 기준으로 충분하면 F02에 범위·기준 버전을 기록한다. 신규 도메인·고위험 시스템에서 별도 기준이나 대외 협의 계획이 필요한 경우 추가 작성한다. |
| [윤리 대안·협의 06-02-F04](../forms/AIDU-AIP-06-02-F04.md) | 일반 영향은 F01~F03으로 처리한다. 중대한 권리·윤리 충돌 또는 직접 협의가 필요한 경우 상세 기록을 작성한다. |

# 3 담당과 기록

### 3.1 인공지능안전관리자의 실무는 [조직 및 역할절차서](../procedure/AIDU-AIP-05-02.md)에 따라 분담한다. 업무 책임자는 자신의 자료와 조치 근거를 작성하고, 총무팀은 문서·교육, 회계팀은 공급자 계약, 영업팀은 고객 의사소통, 개발·운영 담당자는 기술·검증·운영 증거를 연결한다.

### 3.2 기술책임자는 평가·기술 결정과 관련 기록을 검토한다. 대표이사 승인, 독립 검토 및 대리 권한은 해당 절차의 조건을 적용한다. 담당자·개인 연락처·승인일은 이 지침에 고정하지 않고 지정 기록에서 조회한다.

### 3.3 검토 요청에는 대상 버전, 요청하는 결정, 핵심 근거, 미해결 사항·이견, 기한 및 실행 제한을 포함한다. 회의·전자결재·이슈 댓글 등 매체와 관계없이 결정자·시각·결정 내용·대상 버전을 추적할 수 있게 보존한다.

# 4 업무 수행 방법

## 4.1 업무 접수와 통합 기록 구성

### 4.1.1 시스템 책임자는 접수 내용을 다음 네 질문으로 정리한다.

1) 어떤 문제를 해결하며 어떤 AI 출력이 실제 결정에 사용되는가?
2) 직접 사용자와 영향을 받는 사람은 누구이며, 회사·공급자·고객 중 누가 어떤 결정을 하는가?
3) 이전에 검토한 목적·대상·데이터·모델·계약·관할과 달라진 것은 무엇인가?
4) 이번 작업에서 승인받을 범위와 보류할 범위는 어디까지인가?

### 4.1.2 별도 문서 여러 개 대신 하나의 프로젝트 기록을 사용할 때에는 다음 구역을 두고 각 구역에 해당 양식 ID를 표시한다. 사용 도구와 저장 위치는 공식 저장소 지정에 따른다.

| 기록 구역 | 연결할 내용 |
| --- | --- |
| 기본정보 | 시스템 ID·책임자·목적·버전·개시 사유·이전 기록 |
| 요구와 판단 | 적용범위·법적 판정·고객 요구·평가 기준 |
| 평가와 실행 | 리스크·영향·처리·설계·시험·자원·일정 |
| 결정 | 검토 의견·이견·승인 대상·조건·결정자·시각 |
| 후속 확인 | 배포·운영·효과성·재검토·종료·연결 기록 |

### 4.1.3 상태는 작성 중, 검토 요청, 보완, 승인 또는 보류, 실행, 효과 확인, 종료 등 해당 업무에 맞게 식별한다. ‘승인’은 승인된 범위에만 적용하고, 계획 승인·배포 승인·잔여 리스크 수용·시정 종결을 하나의 체크로 대체하지 않는다.

## 4.2 상황·이해관계자·법령 검토 자료 수집

근거 절차: [AIDU-AIP-04-01](../procedure/AIDU-AIP-04-01.md) 4.1~4.5.

### 4.2.1 담당자는 기존 이슈·요구사항 대장의 행을 기준으로 사업·조직·기술·공급자·고객 사용·외부 의무의 변경을 비교한다. 자료에는 출처, 작성 또는 확인일, 실제 확인한 범위를 남긴다. 전망·고객의 요청·회사 계획은 운영 사실과 구분한다.

### 4.2.2 이해관계자는 계약 상대방부터 작성한 뒤, 출력의 판단 대상·데이터 주체·운영자·외주자·당국까지 확장한다. 각 대상에 요구 내용, 적용 이유, 확인 경로, 이행 책임을 연결한다. 학습자를 직접 만나기 어려운 B2B 서비스는 교수자·교육기관 피드백, 이의제기 내역, 사용성 결과 또는 공개 연구를 활용하고 그 자료가 대표하는 범위를 기록한다.

### 4.2.3 법령 적용 판정은 다음 자료 정리 순서로 지원한다.

1) 실제 기능·출력·사용 과정과 회사·공급자·고객의 행위를 명세에서 가져온다.
2) 공식 법령 원문의 조문·시행일·적용 조건과 관련 가이드라인의 성격을 구분해 외부 정보대장에 연결한다.
3) 고영향, 생성형, 안전성 확보 대상 여부를 각각 검토한다. 사내 위험 점수를 법적 분류 칸에 복사하지 않는다.
4) 해당·비해당에는 확인한 사실과 조건을, 미확정에는 확인할 질문·자료·담당·기한을 적는다.
5) Edu Score는 대학·성인 대상이라는 명칭 외에 고객이 점수·AI 작성 확률을 성적·징계·졸업·기회 판단에 사용하는 방식까지 확인한다.
6) 기관 확인 요청이 필요한 경우에는 절차서가 정한 검토·승인을 거쳐 최신 공식 서식·첨부를 준비한다. 사내 양식을 그대로 법정 제출 서식으로 사용하지 않는다.

### 4.2.4 적용 판정과 의무는 [이해관계자·요구사항 대장](../forms/AIDU-AIP-04-01-F02.md)에 연결하고, 충족 증거를 만들어야 할 담당자에게 전달한다. 가이드라인의 예시, 공급자 광고 또는 과거 판정만 있는 경우에는 현행 의무가 충족되었다고 표시하지 않는다.

## 4.3 리스크 식별·평가표 작성

근거 절차: [AIDU-AIP-06-01](../procedure/AIDU-AIP-06-01.md) 4.1~4.4.

### 4.3.1 평가 전에 대상 시스템·버전, 기간·노출 범위, 평가 목적, 적용 기준 버전과 검토자를 적는다. 공통 기준을 적용하는 일반 평가는 [F02](../forms/AIDU-AIP-06-01-F02.md)에 기록하고, 별도 기준이 필요한 경우에만 F06을 추가한다.

### 4.3.2 리스크 한 건은 ‘원인 또는 취약 조건 → 발생 사건 → 영향을 받는 대상과 결과’ 순으로 작성한다. ‘정확도 낮음’과 같은 특성만 쓰지 않고 어떤 사용에서 어떤 피해가 생기는지 적는다. 동일 원인으로 다른 권리·안전 결과가 생기면 구분하거나 하위 시나리오로 연결한다.

### 4.3.3 기존 통제에는 실제 구현되어 작동 증거가 있는 조치만 적는다. 계약 문구, 설정 화면, 시험 결과, 운영 관찰 중 무엇을 확인했는지 구분한다. 계획 중인 조치는 처리안에 두고 현재 위험을 낮추는 근거로 사용하지 않는다.

### 4.3.4 행렬 평가는 다음 순서로 수행한다.

1) 회사·개인·집단·사회별 결과의 심각도와 근거를 기록하고 최댓값을 S로 선택한다.
2) 같은 기간·사용 조건의 시험·운영 근거와 통제 상태로 L을 선택한다. 적은 표본에서 사건이 없었다는 사실만으로 ‘발생하지 않음’이라고 해석하지 않는다.
3) R=L×S를 계산하고 상위 절차의 등급·수용 불가 조건과 대조한다. L과 S는 순서 척도이며 R을 실제 확률이나 기대 손실로 표시하지 않는다.
4) 법령·계약 위반, 필수 보호 통제 미충족 및 심각도 5에 해당하는지 점수와 별도로 확인한다.
5) 현재·처리 후 평가에 같은 기준을 사용한다. 기준이 달라졌다면 변경 근거와 이전 평가의 재검토를 연결한다.

### 4.3.5 가능성의 근거가 부족하면 L·R에 임의 값을 넣지 않는다. 확인된 사용·시험·운영 사실, 가능한 결과, 통제의 효과, 남은 불확실성을 기술하고 정성 판정과 필요한 추가 자료를 적는다. 수용을 요청할 때에는 낮음·보통에 상응하는 이유와 필수 보호의 검증 결과를 제시한다.

### 4.3.6 같은 API·데이터·권한·인력에 의존하는 리스크를 묶어 공통 원인·연쇄 피해를 확인한다. 개별 항목의 점수를 더하거나 평균내는 것으로 결합 위험을 판정하지 않고, 동시에 실패하는 시나리오를 추가한다. 기회는 수혜자·부담자와 새 위험을 함께 작성한다.

## 4.4 처리 계획·SoA·수용 근거 정리

### 4.4.1 리스크 책임자는 [처리안 F03](../forms/AIDU-AIP-06-01-F03.md)에 원천 제거, 범위 축소·중단, 수동 대체, 예방·탐지·피해 감소, 분담 또는 기준 내 보유 중 실행 가능한 대안을 비교한다. 선택 이유, 조치 담당, 자원, 완료 기한, 검증 방법과 실패 시 대응을 적는다.

### 4.4.2 ‘담당자 교육’처럼 결과를 확인하기 어려운 조치는 교육 후 실제로 수행할 행동·평가 방법까지 구체화한다. 기술 통제에는 정상 작동 시험과 통제가 실패하거나 우회되는 시험을 구분하고, 완료 증거와 효과 증거의 위치를 남긴다.

### 4.4.3 [SoA F04](../forms/AIDU-AIP-06-01-F04.md)는 다음 순서로 작성한다.

1) 38개 관리 항목의 의미를 확인하고 적용 범위·리스크·요구사항과 연결한다.
2) 적용할 관리는 실제 수행 방법·책임·구현 상태·검증 증거를 적는다. 절차서 파일의 존재만으로 구현 완료로 표시하지 않는다.
3) 제외할 관리는 활동·위험·의무와 대조한 근거를 적는다. 외부 모델 사용 또는 자체 학습 부재를 일괄 제외 이유로 사용하지 않는다.
4) 부속서에 없는 추가 관리는 구별되는 ID를 부여한다. 같은 증거로 여러 관리를 충족하면 원본을 한 번 보관하고 각각 연결한다.

### 4.4.4 [검증·잔여 수용 F05](../forms/AIDU-AIP-06-01-F05.md)에는 구현 버전, 실제 시험·운영 결과, 남은 위험·2차 영향, 리스크 책임자의 확인 및 기술책임자의 수용 결정을 기록한다. 계획 승인과 수용 결정은 통합 기록 안에서도 구분한다. 기준 미충족이면 보완·범위 제한·중단의 후속 결정을 요청한다.

## 4.5 영향평가·윤리 검토 실무

근거 절차: [AIDU-AIP-06-02](../procedure/AIDU-AIP-06-02.md) 4.1~4.5. 참조: 인공지능 영향평가 가이드라인(2026.1.22 제공본) 11~24쪽, 부록 1·2. [원문과 대응표](../analysis/aims-procedure-revision-basis.md)에 반영 위치를 정리한다.

### 4.5.1 평가자는 사전 준비에서 [계획 F01](../forms/AIDU-AIP-06-02-F01.md)에 대상·범위·판단 기준을 정하고, 본 평가에서 [평가서 F02](../forms/AIDU-AIP-06-02-F02.md)에 시나리오·기본권별 영향을 기록한 뒤, 사후 단계에서 개선·검증·정보 제공·재평가를 연결한다. 기존 시스템 명세·리스크 평가·개인정보 영향평가·공급자 자료는 버전과 적용 범위를 확인하여 재사용하고, 달라진 사용 목적·집단·기능과 자료 공백만 보완한다. 같은 모델을 쓰더라도 서비스 맥락이 다르면 영향 판단을 다시 한다.

### 4.5.2 평가대상은 다음 일곱 항목으로 정의한다. 시스템 명세에 이미 있는 내용은 위치와 버전을 연결하되, 평가자가 실제 사용 범위를 확인할 수 있게 한다.

| 항목 | 작성·확인 방법 |
| --- | --- |
| 제품·서비스 개요 | 기능·입출력·시스템 버전과 외부 모델·연동 시스템을 적는다. |
| 목적 및 필요성 | 해결하려는 문제와 기대 이익을 적고, 그 이익을 받는 주체를 구분한다. |
| 적용 분야 | 교육·채용 등 실제 업무와 고객의 결과 활용 범위를 적는다. 신규 분야는 해당 분야의 사용 조건을 확인한다. |
| 사용 절차 | 입력부터 최종 처리까지 AI가 관여하는 지점, 사람이 검토·확정하는 지점과 실제 권한을 표시한다. |
| 운영기간 및 빈도 | 서비스의 예정·실제 운영기간, 이용 주기·반복 횟수·규모를 적는다. 평가 수행 일정 및 피해 지속 기간은 별도 항목이다. |
| 이용자·피영향자 범주와 특성 | 연령대·숙련도·전문성·언어·접근성·취약성을 가용 자료로 파악한다. 민감 속성을 조사 목적으로 새로 수집하는 근거로 삼지 않는다. |
| 이용자 선택권 | AI 미사용, 결과 거부, 이의제기·수정 요청, 결과 철회의 가능 여부와 담당자·실행 경로·제약을 확인한다. 교육기관의 도입 선택과 학습자 개인의 선택을 구분한다. |

### 4.5.3 피영향자는 직접·간접·의도치 않은 또는 예상치 못한 세 범주로 나누고 해당 이유를 적는다. B2B 서비스에서는 계약 고객, 실제 조작자, 판단 대상, 데이터 주체가 일치하는지 먼저 확인한다. 간접 영향은 결과가 전달되는 다른 업무·사람·집단까지, 의도치 않은 영향은 비사용자·주변 집단·지역사회·환경과 예외적 사용 상황까지 확장하여 찾는다. 아직 대상을 찾지 못한 범주는 검토한 조건과 재확인 계기를 남기고, 모든 대상을 예측했다는 표현을 쓰지 않는다.

### 4.5.4 작동원리는 다음 단계별로 조사하고 F01의 작동원리 목록에 식별자를 부여한다. 설계서·설정·운영 화면·시험·개발자나 운영자 확인 내용의 버전·일자를 근거로 남긴다. 평가 대상에서 사용하지 않는 기능은 제외하고 외부 API를 통해 수행하는 기능은 포함한다. 확인할 수 없는 공급자 내부 동작은 미확인으로 남기며, 추정을 사용하면 그 가정·근거를 구분하여 확인 담당자·기한·영향 범위에 연결한다.

| 단계 | 확인할 사실 |
| --- | --- |
| 데이터 수집 | 어떤 주체의 어떤 자료를 어느 경로·권한·빈도로 받고, 어디에 저장·전달하는가 |
| 분석·판단 | 어떤 모델·규칙·프롬프트로 분류·추론·예측하고, 어떤 입력과 기준으로 결과를 생성하는가 |
| 결정·실행 | 결과가 누구에게 전달되고 어떤 후속 결정·행동에 쓰이며, 자동 확정과 사람의 검토 경계는 어디인가 |
| 상호작용·피드백 | 추천·설명·이의제기·정정·오류 탐지가 어떻게 이루어지고, 피드백이 데이터·모델·기준 변경에 쓰이는가 |

작동원리에는 ‘특정 점수와 평가 의견을 반환한다’처럼 확인 가능한 동작을 적는다. ‘공정하게 평가한다’는 판단은 비교 시험과 근거를 확인한 후 영향 분석에 기록한다. 이미 존재하는 데이터 흐름·명세는 [시스템 수명 주기 및 데이터 관리지침서](AIDU-AIG-08-02.md) 4.1~4.2의 자료를 연결한다.

### 4.5.5 시나리오는 ‘작동원리와 사용 조건 → 위협·사건 → AI 출력과 후속 결정 → 피영향자에게 생기는 결과’ 순서로 작성한다. 정상 사용, 오류·오용·과신, 반복·누적 사용과 예외 상황을 검토하고, 초기 식별에서는 가능성이 낮은 시나리오도 남긴다. F02에 시나리오 ID와 작동원리 ID를 연결한 뒤 현실성·관련성을 검토하여 분석 대상·제외·추가 확인을 구분한다. 낮은 가능성만으로 회복하기 어려운 중대 피해를 제외하지 않는다.

작성 방법의 가상 예: ‘특정 언어 표현에서 채점 오류가 생김 → 교수자가 검토 없이 결과를 확정함 → 해당 표현을 사용하는 학습자에게 성적 불이익이 집중됨’은 평등권 등의 영향을 검토할 후보 시나리오이다. 실제 평가에는 비교 가능한 답안·채점 기준·오류 분포·교수자의 검토 절차·정정 가능성의 근거가 필요하다. 이 예문과 가이드의 Edu Score 예시는 실제 오류, 발생 확률, 고객 범위 또는 회사의 이행 결과를 뜻하지 않는다.

### 4.5.6 잠재적 기본권은 공통 영역과 서비스 맥락에서 찾고, 권리의 보호 내용과 관련된 피영향자를 함께 적는다. 아래 항목은 후보를 찾는 출발점이며 실제 관련성은 시나리오마다 확인한다.

| 검토 범위 | 기본권 후보와 확인할 연결 관계 |
| --- | --- |
| 개인정보·사생활 | 개인정보자기결정권, 사생활의 비밀과 자유: 수집·결합·추론·공개·감시가 개인의 정보 통제나 사적 생활을 어떻게 제한하는가 |
| 차별·배제 | 평등권: 비교 가능한 대상 사이의 불리한 취급·기회 차이가 어떤 조건과 근거로 발생하는가 |
| 교육·표현·전문 활동 | 교육받을 권리, 표현·학문·예술·직업의 자유: 평가·차단·추천·선별 결과가 학습 기회, 표현·연구·창작 또는 직업 선택·수행을 어떻게 제약하는가 |
| 생명·건강·재산·사회 참여 | 생명·건강 관련 권리, 재산권, 정보 접근·집회·결사의 자유 등: 해당 서비스의 결정·행동이 안전·재산적 이익·정보 이용·참여 기회에 어떤 결과를 주는가 |

공정성·투명성·설명가능성·안전성은 영향 원인과 보호 방법을 검토하는 주제로 사용한다. F02의 기본권 칸에는 그 원칙이 보호하려는 구체적 권리를 적고, 관련 기본권을 특정하지 못한 사회·환경·윤리 영향도 별도 결과로 남긴다.

### 4.5.7 기본권 영향은 F02에서 권리와 피영향 집단별로 다음 순서로 판단한다. 동일한 시나리오에 여러 권리가 관련되면 권리별 구역을 반복하고, 집단 간 차이가 있으면 그 차이가 드러나게 구분한다.

1) 해당 권리가 보호하는 구체적 이익과 그 이익을 누리는 사람·집단을 적는다.
2) 어떤 사건·결정·행동이 그 이익을 제약하는지, AI 동작과 후속 업무 사이에 실제 연결이 있는지 확인한다.
3) 그 연결이 성립하는 사용 조건과 근거, 반대 증거·불확실성을 대조한다. AI 출력이 있다는 사실만으로 최종 불이익이나 법적 침해가 확정되었다고 쓰지 않는다.
4) 평가대상 포함·제외·추가 확인을 결정하고 이유·확인 담당자·기한 또는 재검토 조건을 남긴다. 권리 해석이나 충돌을 내부에서 해결하기 어려우면 인공지능안전관리자·기술책임자에게 검토를 요청하여 절차서 4.3.3에 따라 처리한다.

### 4.5.8 영향 수준은 다음 항목을 각각 판단한다. F01에 적용 기준·지표·산출 방식·자료 범위를 먼저 정하고, 반복 평가에는 같은 기준 버전을 사용한다. 기준을 바꾸면 사유와 기존 결과의 비교 가능성을 남긴다.

| 항목 | 작성·판단 방법 |
| --- | --- |
| 영향 규모·심각도 | 영향을 받는 사람·집단의 범위와 개별 불이익의 정도를 함께 적는다. 단순 불편, 정정 가능한 불이익, 기회 상실, 회복하기 어려운 중대 피해처럼 실제 결과와 구제 가능성으로 구분하고 인원수만으로 판단하지 않는다. |
| 영향 기간 | 발생·발견부터 정정·회복까지 예상 시간을 적고, 다음 성적 확정·선발·계약 등 후속 결정 전후에 회복 가능한지 확인한다. 장기·세대 간 영향 가능성은 해당 근거가 있는 경우 기록한다. |
| 발생 가능성 | 관찰·시험 기간, 표본·반복 사용·노출 조건, 해당 사건의 발생 근거를 적는다. 모델 오류율을 개인의 권리 피해 발생 확률로 그대로 쓰지 않는다. |
| 회복·간접·누적 영향 | 이의제기 후 사람의 재검토·정정이 가능한지, 이미 전달된 결정의 회수가 가능한지, 반복 노출·다른 업무로의 전파가 피해를 확대하는지 확인한다. |
| 현재 통제와 불확실성 | 평가일 현재 실제 적용되는 통제, 적용 집단·조건과 시험·운영 증거를 적고, 미확인 자료 및 판단에 미치는 한계를 함께 남긴다. |

정량 자료가 부족하면 추정 수치를 만들지 않고 구체적 조건에 따른 정성 판단과 추가 확인 방법을 적는다. 가이드 부록 1의 4단계 예시 척도는 고정 점수표로 채택하지 않는다. 회사의 5단계 L·S 행렬은 리스크 평가절차의 적용 조건을 충족할 때 별도 리스크 기록에서 사용하며, 기본권별 판단을 단일 평균 점수로 바꾸지 않는다.

### 4.5.9 핵심 여섯 영역의 작업 질문은 다음과 같다. 기본권별 분석과 함께 확인한 자료와 남은 공백을 F02에 남긴다.

| 영역 | 실무 확인 방법 |
| --- | --- |
| 책무성 | 오류 결과를 특정하여 누구에게 정정·중지·고객 통보를 요청할 수 있는지 추적한다. |
| 공정성·차별 방지 | 언어·입력 형식·사용 환경 등에 따라 오류와 부담이 집중되는 조건을 비교한다. 민감 속성의 수집 근거가 없으면 대체 자료와 한계를 사용한다. |
| 투명성·설명 | 이용자가 AI 사용·판단 요인·불확실성·이의제기 방법을 어디서 확인하는지 실제 화면과 대조한다. |
| 개인정보 | 업무 목적에 필요한 입력인지, 외부 전달·보유·삭제 범위를 이용자가 이해할 수 있는지 확인한다. |
| 안전·보안 | 잘못된 출력·정보 노출·중단의 피해가 어디까지 확산되는지 시험·사건 자료로 확인한다. |
| 인간 통제 | 검토자의 시간·정보·수정·중지 권한과 부재 시 대체가 실제 업무에서 가능한지 확인한다. |

### 4.5.10 추가 주제는 사용 맥락에 따라 선택한다. 분야 판단의 타당성이 중요하면 전문적 책임, 접근·선택·존엄에 영향이 있으면 인간적 가치·인간 중심 설계, 공동체·공공 서비스에 영향이 있으면 지역사회 참여, 관할·기본권 충돌이 있으면 법치주의·국제 행동 규범, 자원 사용이나 직무·외주 작업에 영향이 있으면 환경·노동을 검토한다. 모든 일반 평가에 별도의 14개 주제 보고서를 만들지는 않는다.

### 4.5.11 중대한 영향·가치 충돌에는 AI 미사용, 보조적 사용, 자동화·데이터·대상 축소와 중단을 비교한다. [F04](../forms/AIDU-AIP-06-02-F04.md)가 필요한 사안이면 대안별 수혜·부담, 의견·이견, 선택 이유, 실행·검증·회신을 상세히 남긴다. 직접 협의가 어려운 경우 기존 고객 의견·문의·공개 연구를 활용하고 그 자료가 피영향자를 대표하는 범위와 한계를 적는다. 긍정적 이익과 부정적 피해는 각각 남기며 다른 집단의 이익으로 피해를 상계하지 않는다.

### 4.5.12 개선 조치는 시나리오·권리·집단 ID와 리스크 ID에 연결하고 담당자·기한·완료 증거·검증 기준을 정한다. 현재 통제와 계획 중 조치를 나누어 적고, ‘재검토 예정’을 ‘재검토가 작동함’으로 기입하지 않는다. 조치 후에는 동일한 영향 조건으로 재시험·운영 확인을 수행하고, 정정·구제 경로와 잔여 영향을 함께 검토한다. 회사의 수용 불가 조건과 배포 전 필수 통제는 절차서에 따라 승인 전에 확인한다.

### 4.5.13 고영향으로 판정된 경우에는 절차서 4.4.3의 일곱 항목을 F02의 대응표로 연결한다. AIMS 영향평가의 회사 필수 수행, 법률상 노력의무, 사내 리스크 등급을 각각 구분한다. 가이드의 시행령안 인용 대신 절차서의 현행 법령 항목을 적용하고, 다른 평가·인증이 있다는 사실만으로 대응표의 미작성 항목을 충족 처리하지 않는다.

### 4.5.14 [제공·갱신 F03](../forms/AIDU-AIP-06-02-F03.md)에 수신자·공개 범위·제공 근거·승인 버전·이의제기 및 구제 경로를 정리한다. 전체 보고서의 자율 공개, 계약·적법한 요청에 따른 제출, 필요한 안전·권리 정보 제공과 별도 법정 게시 사항을 구분한다. 개인정보·영업비밀을 제외하더라도 필요한 위험·한계·구제 안내가 빠지지 않는지 확인한다. 평가와 판단 근거는 정보 및 기록관리절차에 따라 보유하고, 운영 지표·불만·사고·사용 변경이 생기면 영향 조건과 조치 효과를 다시 확인하여 F02·F03 및 관련 운영 절차·설정을 갱신한다.

## 4.6 방침·목표·자원·역량의 실행 지원

근거 절차: [리더십·방침](../procedure/AIDU-AIP-05-01.md), [목표·변경](../procedure/AIDU-AIP-06-03.md), [자원](../procedure/AIDU-AIP-07-01.md), [역량·교육](../procedure/AIDU-AIP-07-02.md).

### 4.6.1 방침 검토 자료는 사업 목적·요구·위험의 변화, 기존 원칙의 실행 결과, 필요한 변경으로 나누어 작성한다. 실제 방침은 [방침 양식](../forms/AIDU-AIP-05-01-F01.md)으로 별도 작성하고 관련 목표·책임·공개용 버전과 연결한다.

### 4.6.2 목표에는 기준선·기대 결과·측정 방법·기한·책임·자원을 적는다. 단순 오류율 외에 정정 완료, 감독 가능성, 보유기한 준수 등 목표 목적에 맞는 지표를 선택한다. 실적 자료가 없으면 기준선 확보 계획을 적고 임의 성과를 채우지 않는다. 반기 또는 승인된 계획 주기에 진행 상황을 확인하고 연간 종합 평가에 연결한다.

### 4.6.3 자원 신청에는 필요한 작업·기간·현재 부족량·대안과 비용을 적는다. 접근권한은 업무에 필요한 최소 범위와 종료일을 요청하고 신청자가 자신의 요청을 단독 승인하지 않는다. 실제 계정 목록과 승인 기록을 대조하여 부여·회수 누락을 찾는다.

### 4.6.4 역할 배치 시 수행자·참여자·검토자·승인자와 겸임을 확인한다. 개발·검증 참여는 회의 참석뿐 아니라 검토한 범위·의견·이견의 기록으로 남긴다. 자체 업무의 내부심사는 배정하지 않는다. 인원이 부족하면 적격자의 별도 검토·외부 지원을 상위 절차에 따라 요청한다.

### 4.6.5 교육 결과는 출석 자료와 업무 수행 능력을 구분한다. 역할에 맞춰 고지 위치 설명, 의심 출력의 사람 재검토, 접근 회수, 오류 보고·중지·복구 등 짧은 실습을 실시하고 기준 충족·부족·추가 조치를 기록한다. 실습 자료는 합성·비식별 자료를 우선 사용한다.

## 4.7 문서·증거 등록과 승인본 관리

근거 절차: [AIDU-AIP-07-03](../procedure/AIDU-AIP-07-03.md) 4.1~4.7.

### 4.7.1 작성자는 [양식 원본](../forms/README.md)을 복사하거나 승인된 업무 시스템에서 같은 핵심 항목을 구성한다. 기록 ID, 양식·기록 버전, 대상 시스템, 작성자·작성일, 상태·접근 등급, 연결 기록과 보유 기준을 입력한다. 승인·시행일은 실제 결정 이후에 입력한다.

### 4.7.2 문서·기록 관리대장에서 다음을 확인한다.

1) 같은 제목의 여러 사본이 있으면 현재 유효본과 이력본을 구분한다.
2) 링크를 수신자 권한으로 열어 내용·버전·첨부에 접근 가능한지 확인한다.
3) 변경 가능한 웹 페이지·공급자 조건은 확인일·판을 식별하고, 판단에 사용한 내용의 허용된 사본 또는 변경 이력을 보관한다.
4) 채팅·이메일 결정은 필요한 부분을 공식 기록에 연결하고 결정자와 대상 버전을 확인한다. 도구 사용 사실만으로 공식 저장소 승인을 대신하지 않는다.
5) 증거 화면·로그를 첨부하기 전에 비밀키·불필요한 개인정보·고객 비밀이 포함되었는지 확인한다.

### 4.7.3 정정은 원래 기록을 지우지 않고 정정자·시각·사유·내용을 연결한다. 보유·삭제 기준은 정보 유형별로 등록하고 관리 증거와 원본 개인정보를 분리한다. 고영향 책무 증거의 장기 보관으로 학습자 원문 보유를 일괄 연장하지 않는다. 삭제 실행은 AIG-08-02 4.14를 따른다.

### 4.7.4 지침의 작업 방법을 바꾸면 영향을 받는 절차·양식·교육·검증을 확인하여 개정 요청한다. 대표이사의 실제 승인 전에는 작성안을 시행본으로 배포하지 않는다. 이 지침 작성으로 새로운 승인·회람 이력을 생성하지 않는다.

## 4.8 고객·공급자·대외 제출 자료 정리

### 4.8.1 공급자 검토는 해당 계정·플랜·기능·지역의 공식 조건과 실제 설정을 한 곳에 연결한다. 공개 이용약관·처리 설정·기술문서·인증 자료와 회사 통합 시험으로 확인할 수 있는 항목을 우선 사용한다. 확보하지 못한 항목은 한계와 회사 측 보완을 적고, 모든 표준 API 공급자에게 별도 감사나 비공개 자료 제출을 일률 요구하지 않는다.

### 4.8.2 고객 책임 분담에는 제공 목적, 최종 결정자, 입력·평가 기준, 고지·표시 경로, 사람의 검토·정정, 보유·삭제 및 사건 연락을 정한다. 고객 약정과 실제 화면·업무가 다른 경우 영업 담당자는 차이를 기술책임자에게 전달한다.

### 4.8.3 고지·설명 자료는 대상자가 도입·사용·결과 해석·구제 중 어떤 결정을 해야 하는지에 맞추어 작성한다. 목적·AI 사용·한계·필요한 사람의 확인·정정 경로가 자료의 실제 화면·문서에 포함되는지 AIG-08-02 4.8에서 시험한다. 고영향 게시 정보에는 실제 감독자 지정 기록과 일치하는 내용을 사용한다.

### 4.8.4 대외 제출·회신은 수신 기관·목적·근거·범위·기한을 확인한 뒤 승인된 버전으로 수행한다. 공개본과 제한본을 구분하고 제출본·접수 확인·보완 요청을 연결한다. 내부 검토 양식과 법정 서식, 일반 상담과 공식 판정 회신을 구분한다. 법정 기한은 요구사항 대장에서 확인하며 가이드라인 예시를 기한으로 입력하지 않는다.

## 4.9 연간 통합 점검과 성과 자료 작성

근거 절차: [절차서 공통 운영](../procedure/AIDU-AIP-00.md) 1.4, [성과·준수평가](../procedure/AIDU-AIP-09-01.md).

### 4.9.1 총무팀과 인공지능안전관리자는 연간 일정에 다음 작업의 순서·담당·입력 기한을 연결한다. 동일 자료로 여러 활동을 지원할 수 있으나 판단·승인 주체는 구분한다.

| 작업 순서 | 준비할 자료와 확인 방법 |
| --- | --- |
| 상황·요구·방침·역할 확인 | 이전본과 실제 변경을 비교하고 미확정 의무·공백을 확인한다. |
| 리스크·영향·공급자·자원·역량 점검 | 전제·사용·기술·사건 변화와 실제 증거를 대조한다. |
| 성과·준수 종합 | 월별 운영 자료·목표 진행·삭제·구제·시정 결과를 취합하고 근거 공백을 표시한다. |
| 내부심사 | 위험·변경을 고려한 표본과 독립 심사원을 배정하여 실제 수행을 추적한다. |
| 경영검토 | 이전 조치·변화·성과·심사·개선·자원에 대한 대표이사의 결정을 기록한다. |
| 후속 반영 | 결정된 목표·역할·문서·조치의 담당·기한·검증을 연결한다. |

### 4.9.2 운영 이상 감시, 월별 운영 결과 검토, 단기 보유 만료 확인과 진행 중 시정조치 추적은 연간 점검과 별도로 수행한다. 목표는 반기 또는 계획 주기로 확인하고, 중대한 변경·사건·의무 변화는 다음 정기일을 기다리지 않는다. 추가 전사 분기 보고나 별도 회의를 이 지침만으로 신설하지 않는다.

### 4.9.3 성과 표에는 분모·측정 기간·모델/설정·집단·표본·누락을 함께 적는다. 비교 기간의 기준이 달라졌으면 차이를 표시한다. 데이터가 없는 값은 0이나 양호로 채우지 않고 미측정·비교 불가와 확보 계획을 남긴다. 성능 수치와 AIMS의 통제 효과·권리 구제·기한 준수는 각각 판단한다.

## 4.10 내부심사·경영검토·시정조치 지원

### 4.10.1 심사 준비 시 [심사계획·배정표](../forms/AIDU-AIP-09-02-F02.md)에 대상 업무와 심사원이 실제 수행·검토·승인한 업무를 대조한다. 직함이 다르다는 이유만으로 독립성을 인정하지 않는다. 신규·변경·사건과 연결된 실제 사례를 표본으로 선정한다.

### 4.10.2 심사에서는 최소 한 건의 요구사항부터 판단·시험·승인·운영·정정·종료까지 연결을 따라간다. 실행되지 않은 단계는 준비 상태와 미실시 사유를 확인한다. 발견사항은 ‘요구 → 확인한 사실·증거 → 차이·영향’으로 기록하고, 심사 종료 후 5영업일 이내 보고 및 후속 확인은 [내부심사절차서](../procedure/AIDU-AIP-09-02.md)를 따른다.

### 4.10.3 경영검토 입력은 [입력자료표](../forms/AIDU-AIP-09-03-F01.md)의 필수 항목별로 기존 보고서를 연결한다. 각 안건에 판단이 필요한 내용·대안·자원·남은 위험을 적고, [결과표](../forms/AIDU-AIP-09-03-F02.md)에 대표이사의 결정·담당·기한·효과 확인을 남긴다. 단순 자료 수신을 경영검토 완료로 처리하지 않는다.

### 4.10.4 부적합은 요구 미충족, 개선 기회는 위반 없이 더 나은 결과가 가능한 경우로 구분하고 근거 부족은 추가 확인으로 표시한다. 긴급 건은 즉시 보호에 연결하고 일반 건의 책임·조사 일정은 [시정조치절차서](../procedure/AIDU-AIP-10-01.md)의 기한에 따라 정한다.

### 4.10.5 원인분석에는 시간순 사실, 최초 오류 조건, 탐지·승인에서 놓친 이유, 같은 조건을 쓰는 다른 시스템을 포함한다. 즉시 시정과 재발 방지를 구분하고 검증자가 실제 재시험·운영 관찰로 효과를 확인한다. 종결 전 피해 구제, 고객 후속 결정, 관련 평가·문서 갱신까지 확인한다.

## 4.11 불만·우려 접수와 사건 연결

### 4.11.1 접수자는 제보자가 누구인지 확인하는 데 필요한 최소 정보와 대상 결과·시각·요청 내용을 기록한다. 안전·권리·정보 보호 피해가 진행 중이면 담당 배정을 기다리지 않고 기술책임자에게 즉시 보고한다. 내부 우려는 [05-02-F04](../forms/AIDU-AIP-05-02-F04.md), 고객·피영향자 이의는 [08-01-F07](../forms/AIDU-AIP-08-01-F07.md)에 연결하며 동일 건을 중복 조사하지 않는다.

### 4.11.2 고객 이의 접수 안내는 2영업일 이내의 내부 목표와 더 빠른 법령·계약 기한을 확인한다. 접수 안내 목표를 최종 처리 기한이나 법정 기한으로 바꾸지 않는다. 회신에는 확인된 사실, 검토 범위, 다음 안내 시점과 추가 제기 경로를 포함한다.

### 4.11.3 결과 정정은 같은 모델에 동일 요청을 재실행하는 것만으로 끝내지 않는다. 적격한 사람이 입력·기준·추가 자료·모델 한계를 검토하고 정정 범위·고객 최종 판단·회신을 연결한다. 제보자·피영향자에게 불필요한 증빙이나 개인정보를 반복 요구하지 않도록 기존 자료를 활용한다.

# 5 양식과 기록의 사용

### 5.1 이 지침은 [기존 양식 60종](../forms/README.md)의 작성 방법을 보완한다. 지침 전용 양식을 추가하지 않으며 실제 기록은 해당 절차의 양식 또는 핵심 항목을 충족하는 통합 기록으로 관리한다.

### 5.2 상세 작업표·계산 결과·면담 질문·시험 첨부가 필요한 경우에는 근거 양식의 연결 기록으로 관리한다. 실제 운영 결과·담당자·서명·방침을 본 지침에 붙이지 않는다.
