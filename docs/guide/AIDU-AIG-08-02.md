# 1 목적

### 1.1 이 지침서는 AI 시스템의 요구 정의, 설계·구현, 데이터 준비, 확인·타당성 검증, 배포, 운영·변경, 사건 대응 및 종료에 필요한 세부 작업 방법과 확인 증거를 정한다.

### 1.2 단계 전환·승인권자·수용 기준은 [인공지능경영활동절차서](../procedure/AIDU-AIP-08-01.md)와 관련 절차를 적용한다. 이 지침의 시험 방법과 점검표는 해당 기준의 충족 여부를 확인하는 데 사용한다.

# 2 적용범위와 적용 수준

### 2.1 외부 모델 API를 사용하는 회사 서비스, 내부 업무용 AI, 향후 자체 학습·파인튜닝·지속적 학습을 도입하는 시스템에 적용한다. 시스템마다 실제 수행하는 활동을 명세에 표시하고 해당 활동의 작업 항목을 선택한다.

| 활동 | 적용할 작업 |
| --- | --- |
| 외부 모델 API 통합 | 목적·입출력·프롬프트·설정·공급자 조건·통합 시험·변경 감시·데이터 전송 통제 |
| 검색·지식 결합 기능 | 문서 출처·권리·접근 구분·검색 품질·인덱스 계보·원문 삭제의 전파 |
| 자체 학습·파인튜닝 | 학습 데이터 권한·분할·실험·모델 계보·평가 독립성·재현성 |
| 운영 중 지속적 학습 | 업데이트 경계·지속적 검증·자동 반영 조건·중지·안정 버전 복원 |
| 내부 업무용 AI | 승인된 도구·사용 목적·입력 가능 정보·결과 확인·외부 제공 여부 |

### 2.2 학습하지 않는 서비스는 학습 실험 기록을 만들 필요가 없다. 다만 프롬프트·검색·규칙을 조정하는 개발 데이터, 최종 테스트 및 운영 데이터의 구분과 외부 모델 통합 검증은 수행한다.

### 2.3 기준값·표본 수·경보 임계값·복구 목표·호출 한도는 사용 목적과 위험에 맞춰 시험·운영 계획에서 정한다. 이 지침의 예시 지표를 모든 서비스의 일률 합격 기준으로 사용하지 않는다.

# 3 담당과 작업 준비

### 3.1 시스템 책임자는 명세와 작업 간 연결을 관리한다. 개발·데이터 담당자는 구현과 데이터 근거를, 운영·검증 담당자는 시험·배포·감시·복구 증거를 작성한다. 인공지능안전관리자는 리스크·영향·권리·정보 보호를 검토하고 회계·영업·총무 담당자는 계약·고객·기록·교육을 분담한다.

### 3.2 개발과 검증 참여, 겸임 시 추가 검토, 기술책임자의 승인 및 대표이사 상신은 [조직 및 역할절차서](../procedure/AIDU-AIP-05-02.md)를 따른다. 개발/AI팀과 운영팀의 참여 기록에는 담당자가 실제 검토한 범위와 의견·이견을 구분한다.

### 3.3 작업 전에는 승인된 목적·환경·계정·권한·데이터·작업 범위와 미해결 보호 조건을 확인한다. 시험에 실데이터가 필요하면 사용 근거·최소 범위·보유기간을 먼저 확인한다. 도구·저장소·공급자의 현재 사용 사실만으로 승인된 상태를 추정하지 않는다.

# 4 수명주기별 작업 방법

## 4.1 시스템 명세·요구·단계별 증거 구성

### 4.1.1 [시스템 명세 F01](../forms/AIDU-AIP-08-01-F01.md)에 입력, 전처리, 외부 모델·검색, 후처리, 출력, 사람의 결정 및 후속 동작을 순서대로 적는다. 각 구간에 처리 주체·경계·데이터·권한·실패 시 동작을 연결한다. AI 모델과 규칙·화면·계약·인간 업무를 포함한 전체 시스템을 구분한다.

### 4.1.2 요구사항에는 ID를 부여하고 각 요구에 구현 위치·시험 ID·결과·승인 기록을 연결한다. ‘공정하게 평가’처럼 바로 확인하기 어려운 요구는 평가 대상·오류 유형·집단 또는 사용 조건·관찰 방법·판정 기준으로 나눈다. 적용되지 않는 특성은 실제 기능과 이유를 남긴다.

### 4.1.3 버전 묶음에는 코드 변경 식별자, 모델/API 식별정보, 프롬프트·규칙·평가기준, 데이터셋·지식 인덱스, 실행 환경·주요 설정을 포함한다. 비밀키 값은 넣지 않고 비밀 관리 위치와 권한만 연결한다. 외부 모델의 세부 버전을 알 수 없으면 공급자 식별정보·사용 시각·확인 가능한 판과 한계를 기록한다.

### 4.1.4 다음 단계로 넘길 때 다음 증거를 한 곳에서 찾을 수 있게 한다.

| 단계 | 작업자가 정리할 증거 | 결손 시 처리 |
| --- | --- | --- |
| 착수 | 목적·대상·법적 판정·평가 범위·자원 | 사실·기준을 보완하고 허용 시험 범위를 확인 |
| 개발 | 데이터·공급자 조건·설계·처리 조치·검증 계획 | 미승인 데이터·기능을 분리하고 검토 요청 |
| 검증 | 고정한 대상 버전·독립 테스트·사전 판정 기준 | 시험 대상 또는 기준을 확정한 뒤 수행 |
| 배포 | 시험 결과·잔여 위험·영향·고지·감독·복구·삭제 준비 | 필수 조건 미충족 기능의 제공 보류 |
| 변경·재개 | 변경 영향·재시험·통지·복원 가능 범위 | 제한 유지 또는 이전 안정 구성 적용 검토 |
| 종료 | 고객 전환·미해결 권리·반환·삭제·자원 회수 | 미완료 작업과 잔여 책임을 명시 |

## 4.2 데이터 목록과 흐름 확인

### 4.2.1 데이터 담당자는 [데이터 관리표 F02](../forms/AIDU-AIP-08-01-F02.md)에 데이터셋 또는 처리 목적별 항목을 만든다. 내용에는 출처·제공자·수집 근거·허용 용도·제한·민감성·최소 필드·담당자·보유 기준·연결 시스템을 포함한다.

### 4.2.2 실제 전달 경로를 애플리케이션 설정과 대조한다. 데이터베이스·파일·첨부·검색 인덱스·벡터·캐시·임시 파일·작업 큐·실패 메시지·로그·백업·공급자 저장소 중 해당하는 위치를 표시한다. 처리 위치와 관리 주체를 구분하여 회사 저장 지역만으로 외부 API의 처리 지역까지 확인되었다고 보지 않는다.

### 4.2.3 목적이 수집 당시와 다른 데이터는 시험·분석·학습·지원 등 새 용도의 허용 여부를 확인한다. 고객에게 받은 데이터라는 사실만으로 회사의 모든 연구·모델 개선에 사용할 수 있다고 해석하지 않는다. 근거가 없거나 보유기한이 지난 데이터는 새 작업에 투입하지 않는다.

### 4.2.4 외부 데이터·공개 자료에는 원본 위치·취득일·권리·이용 조건·변경 이력을 남긴다. 접근 가능성과 재사용 권한을 구분한다. 데이터가 변경되면 품질·대표성·사용권·기존 평가의 유효성을 다시 확인한다.

## 4.3 품질 점검·전처리·가명처리

### 4.3.1 원본을 승인된 제한 영역에서 식별한 후 작업 사본과 변환 버전을 구분한다. 다음 점검을 용도별로 수행하고 오류 수·비율·제외·보정·남은 한계를 F02에 기록한다.

| 항목 | 작업 방법 |
| --- | --- |
| 형식·완전성 | 필수 필드, 자료형, 문자 인코딩, 길이·범위, 빈 값과 중복 키를 검사한다. |
| 정확성·일관성 | 문항·기준·답안의 연결, 단위·날짜·코드의 일치, 참조 대상 누락을 확인한다. |
| 대표성·최신성 | 목적에 맞는 언어·입력 형식·과제·환경·기간의 분포와 빠진 조건을 비교한다. |
| 라벨·평가기준 | 기준 작성자의 전문성, 적용 범위, 기준 버전, 평가자 간 불일치와 해결 근거를 확인한다. |
| 오염·유해 내용 | 평가 정답 노출, 악성 지시·스크립트·파일, 잘못된 출처·과도한 민감정보를 찾는다. |
| 변환 영향 | 전처리 전후 일부 표본을 대조해 정답 의미·근거·집단 특성이 의도치 않게 바뀌지 않았는지 확인한다. |

### 4.3.2 결측·오류·중복은 원인과 목적에 따라 거절, 격리, 정정 요청, 제외 또는 보정으로 처리한다. 결측값을 0점·정답·정상 상태로 자동 대체하지 않는다. 보정·증강·합성 자료에는 방법·버전·대상·검증·원자료와의 관계를 표시한다.

### 4.3.3 외부 API 전송 전 가명처리는 다음 순서로 수행한다.

1) 이름·학번·이메일 등 직접 식별자와 자유서술·첨부·메타데이터에 포함될 식별 가능 정보를 분리한다.
2) 업무에 필요한 대상 연결은 별도의 임의 식별자로 대체하고, 원래 값과의 연결정보는 전송 데이터에서 제거하여 별도 권한으로 보호한다.
3) 답안 본문의 인명·연락처·주소 등은 실제 처리 목적과 의미 보존을 고려해 제거·치환한다. 자동 탐지의 누락·과잉 치환을 합성 자료와 허용된 표본으로 점검한다.
4) 치환 후 점수·결과 연결이 다른 사람에게 뒤바뀌지 않는지, 식별정보가 오류 메시지·파일명·추적 로그에 남는지 확인한다.
5) 승인된 전송 필드 목록과 실제 요청 본문·첨부·헤더를 비교한다. 숨은 메타데이터·디버그 로그·도구 호출의 추가 전송도 확인한다.
6) 식별정보 제거 실패 또는 연결 오류가 있으면 해당 전송을 보류하고 격리·정정한다. 가명 데이터도 재식별 가능성이 있으므로 보호·보유 조건을 유지한다.

### 4.3.4 가명처리 검증 증거에는 검사 항목·방법·실패 유형·개수·수정 결과를 남긴다. 증거를 위해 원래 개인정보를 일반 이슈·메신저·소스 저장소에 복사하지 않는다.

## 4.4 데이터 분할·라벨·검색 자료 관리

### 4.4.1 먼저 모델·프롬프트·규칙을 조정할 개발/검증 데이터와 최종 성능을 확인할 테스트 데이터를 구분한다. 자체 학습이 있으면 훈련 데이터도 별도로 식별한다. 운영 데이터는 목적·권한을 검토하여 재사용하기 전까지 어느 개발 세트에도 자동 편입하지 않는다.

### 4.4.2 같은 사람·문서·유사 문항·원본에서 나온 증강 데이터가 서로 다른 세트에 흩어지지 않는지 확인한다. 단순 파일 해시 외에 의미상 유사한 문항과 같은 원본의 파생자료도 검토한다. 미래 자료를 예측하는 사용에서는 시간 순서와 이용 당시 알 수 있는 정보가 유지되도록 분할한다.

### 4.4.3 최종 테스트를 보고 프롬프트·모델·기준을 조정했다면 그 테스트는 다음 버전의 독립적인 최종 평가 근거로 그대로 재사용하지 않는다. 새 홀드아웃 확보 또는 승인된 대체 검증을 계획하고 한계를 기록한다. 데이터가 적어 교차검증 등을 사용하면 분할 단위·반복·선택 과정과 최종 판단의 독립성을 시험 전에 검토받는다.

### 4.4.4 라벨·기준 답안은 작성 기준·담당·버전과 함께 관리한다. 여러 평가자의 불일치가 중요한 경우에는 독립 평가한 표본의 일치·차이를 확인하고, 원래 판단과 조정 이유를 보유한다. 조정 후 결과만 남겨 기준의 불확실성을 숨기지 않는다.

### 4.4.5 검색·지식 결합 기능을 사용하면 문서 출처·유효기간·권한·추출/분할 방식·인덱스 버전을 연결한다. 다른 고객의 문서가 검색되거나 삭제한 원문이 인덱스·캐시에 남는지 확인한다. 검색 결과의 악성 지시는 업무 데이터로 처리하고 시스템 권한 지시로 승격하지 않도록 통합 시험에 포함한다.

## 4.5 외부 API·구현·실험 관리

### 4.5.1 API 담당자는 [공급자 검토 F04](../forms/AIDU-AIP-08-01-F04.md)의 승인 조건과 실제 계정·플랜·엔드포인트·모델·처리 지역·보관·학습 활용·재위탁 조건을 대조한다. 공개 문서가 어떤 제품·기능에 적용되는지 확인하고 확인일·설정 증거·계약 범위를 남긴다. 한 계정이나 기능의 조건을 다른 기능까지 확대 적용하지 않는다.

### 4.5.2 보관 제외와 학습 미활용은 각각 확인한다. 공급자의 표준 약관·설정·공개 문서 및 회사 통합 시험으로 평가할 수 있으나, 필수 조건의 예외나 미확인 범위가 있으면 인공지능안전관리자·기술책임자에게 검토를 요청한다. Edu Score의 회사 요구가 특정 공급자에서 충족된다는 사실을 근거 없이 전제하지 않는다.

### 4.5.3 구현 시 입력·출력 형식, 허용 값·길이·범위, 타임아웃·재시도·중복 처리·오류 전파를 정한다. 공급자 실패·응답 파싱 실패·근거 부족이 정상 점수나 확정 판단으로 저장되지 않는지 확인한다. 재시도는 같은 작업의 중복 평가·중복 과금·다른 결과 확정을 유발할 수 있으므로 요청 식별·상태와 함께 관리한다.

### 4.5.4 프롬프트·도구 호출은 버전 관리한다. 사용자 입력과 운영 지시의 경계를 구분하고 도구의 조회·변경·외부 전송 권한을 필요한 범위로 제한한다. 비밀키는 승인된 비밀 관리 수단에 보관하고 프롬프트·코드·일반 로그에 넣지 않는다. 공격 시험은 승인된 시험 환경·합성 자료로 수행한다.

### 4.5.5 후보 비교·실험은 다음 순서로 남긴다.

1) 비교 목적·기준선·대상 조건·예상 효과와 보호 제약을 정한다.
2) 후보 모델·프롬프트·설정·데이터 버전·환경·시각을 식별한다.
3) 같은 조건과 독립된 평가 자료에서 결과·실패·변동을 비교한다.
4) 선택 이유·기각 이유·추가 위험·재현 한계를 기록하고 선택 후 최종 검증 대상을 고정한다.
5) 자체 학습·파인튜닝이면 학습 권한·알고리즘·초매개변수·훈련 코드·연산량의 확보 가능한 근거·모델 계보를 추가한다.

## 4.6 시험 계획과 결과의 추적

### 4.6.1 [시험 F03](../forms/AIDU-AIP-08-01-F03.md)에 요구사항·위험별로 다음을 정하고 시험 전에 기술책임자의 검토·승인을 받는다.

| 구분 | 계획에 작성할 내용 |
| --- | --- |
| 대상 | 시스템·모델·프롬프트·데이터·설정·연동·사람 업무의 버전·범위 |
| 자료 | 표본의 출처·권리·기간·조건·집단·기준 답안과 독립성 |
| 방법 | 정상·경계·오용·실패 시나리오, 반복·집계·사람 평가 방식 |
| 판정 | 지표·분모·허용 범위·필수 보호·보류·미실시 처리 |
| 수행 | 담당·환경·일정·개발/운영 참여·겸임 추가 검토 |
| 증거 | 실행 식별자·재현 조건·실패·수정·회귀 시험·결과 위치 |

### 4.6.2 명세대로 구현되었는지 확인하는 시험과 실제 사용 목적을 충족하는지 확인하는 타당성 시험을 구분한다. 모델 결과만 보지 않고 데이터 연결·후처리·표시·사람 판단·고객 연동까지 시험한다.

### 4.6.3 시험자는 실제 실행 버전·조건·시각·결과·편차·증거를 기록한다. 미실시, 실행 실패, 판정 실패, 합격을 구분하고 원래 실패 결과와 수정·재시험을 연결한다. 시험 결과에 맞춰 합격 기준을 뒤늦게 낮추지 않는다. 기준 변경이 필요하면 사유·영향·승인 후 해당 범위를 다시 평가한다.

### 4.6.4 보호에 중요한 시나리오는 다음을 기준으로 선택한다.

| 시나리오 | 확인할 동작 |
| --- | --- |
| 누락·긴 입력·다국어·형식 오류 | 잘못된 확정 결과 대신 오류·보류·정정 경로로 연결되는지 |
| 분포 밖 입력·새 분야·새 평가 기준 | 허용 범위를 식별하고 추가 검토 또는 사용 제한이 되는지 |
| 반복 호출·비결정적 출력 | 점수·판정·설명이 달라지는 범위와 불이익 영향이 허용 기준 안인지 |
| 적대 입력·프롬프트 주입·조작 파일 | 지시 경계·권한·출력 제한·정보 보호가 유지되는지 |
| 외부 API 장애·지연·버전 변화 | 실패 전파·수동 대체·중복 방지·경보·회귀 확인이 동작하는지 |
| 고객·대상 연결 오류 | 다른 사람·고객의 데이터와 결과가 섞이지 않는지 |
| 감독자 부재·과신·개입 지연 | 대리·보류·수정·중지·재개 경로가 실제로 가능한지 |
| 삭제·복구·재처리 | 기한이 지난 자료가 되살아나거나 새 결과가 재생성되지 않는지 |

## 4.7 성능·공정성·교육 평가의 검증

### 4.7.1 사용 목적과 실패 비용에 맞는 지표를 선택한다. 다음은 지표를 계산·해석하는 방법이며 회사 공통 합격값을 정하는 표가 아니다.

| 검증 대상 | 계산·비교 방법 | 해석 시 확인할 사항 |
| --- | --- | --- |
| 수치 점수 오차 | 기준 점수와 예측 점수의 절대 차이 합을 유효 표본 수로 나눈 평균절대오차(MAE), 승인된 허용 오차 이내 비율 | 문항별 배점·중요도·큰 오차·통과선 전후의 결과를 함께 확인 |
| 판별 오탐·미탐 | 오탐률 FP/(FP+TN), 미탐률 FN/(FN+TP) | 무엇을 양성으로 정했는지 먼저 정의하고 분모가 0이면 산출 불가로 표시 |
| 반복 안정성 | 같은 입력·버전을 반복한 점수 분포·판정 변경 건수·설명 모순 | 평균뿐 아니라 극단값·불이익 결정 변경과 재현 한계 확인 |
| 집단·사용 조건 차이 | 같은 정의의 지표를 언어·입력 형식·사용 환경 등 관련 조건별 비교 | 표본 수·대표성·오차 범위·수집 근거가 부족하면 공정성 입증으로 단정하지 않음 |
| 근거·피드백 품질 | 기준·자료에 근거한 설명, 잘못된 사실·부적절한 조언·누락을 평가 기준에 따라 사람 검토 | 평가자·기준·불일치와 처리 결과를 추적 |
| 응답·복구 | 요청부터 사용 가능한 결과까지의 지연 분포·실패 비율·복구 시간 | 실패·타임아웃을 평균에서 조용히 제외하지 않고 별도 보고 |

### 4.7.2 표본 수와 반복 횟수는 목적·변동성·중대 오류·관련 집단을 고려해 사전에 정한다. 작은 표본이나 알려진 편향이 있으면 결론의 범위를 제한하고 추가 검증·사람 검토·사용 범위 축소를 판단한다. 불확실성이 크다는 이유로 필요한 필수 보호 검증을 생략하지 않는다.

### 4.7.3 Edu Score의 시험은 실제 지원 기능별로 구성한다.

1) 객관식·단답형은 허용 답안·표기 변형·부분점수·빈 답안·다중 답안·기준 버전의 처리를 대조한다. 규칙 기반 기능과 AI 기능을 구분한다.
2) 서술형·에세이는 평가 기준이 학습 목표를 측정하는지 분야 검토를 받고, 기준 답안·평가자의 판단과 비교한다. 길이·문체·언어·표현 차이가 내용과 무관하게 점수를 바꾸는지 확인한다.
3) AI 작성 확률은 참값을 신뢰할 수 있는 자료의 범위와 오탐·미탐을 구분한다. 판별 오류가 징계·낙인·성적에 미치는 영향을 검토하고 단독 확정 근거 사용을 제한하는 화면·안내·업무를 시험한다.
4) 제한적 피드백은 평가 근거와 일치하는지, 없는 사실을 생성하는지, 허용 범위를 벗어난 조언을 하는지 점검한다.
5) 점수 수정·이의제기 결과가 올바른 학습자·문항·고객의 최종 결과에 전달되는지 확인한다.

### 4.7.4 다른 서비스는 해당 분야의 성공·피해·결정 기준으로 시험을 다시 설계한다. 교육 평가의 기준 답안이나 합격값을 다른 서비스에 복제하지 않는다. 외부 모델의 일반 벤치마크는 참고 자료로 연결하되 회사 시스템·실제 목적의 검증을 대신하지 않는다.

## 4.8 고지·설명·인간 감독의 사용 시험

### 4.8.1 [F09](../forms/AIDU-AIP-08-01-F09.md)의 적용 판정과 승인된 안내를 기준으로 최초 사용 화면, 결과 화면, 다운로드·공유, API 응답과 고객 LMS 표시를 확인한다. 사전 고지, 생성형 결과물 표시, 실제와 구분하기 어려운 가상 콘텐츠 고지 중 해당하는 항목을 각각 추적한다.

### 4.8.2 시험자는 실제 이용자 권한·화면 크기·언어·접근 수단으로 안내가 보이고 이해 가능한지 확인한다. 기계 판독 표시를 쓰는 경우 사람에게 제공할 안내도 함께 확인한다. 중간 시스템이 표시를 제거하거나 고객 화면에 전달하지 않는 경우에는 책임 분담·수정·재시험을 요청한다. 예외 적용은 상위 절차에 따른 근거·범위와 일치하는지 확인한다.

### 4.8.3 설명 자료는 목적·주요 판단 요인·데이터 개요·성능·한계·정정 방법을 대상자별로 확인한다. 실제 시험과 다른 성능 주장, 확인할 수 없는 내부 추론, 생성된 이유 설명의 과장, 개인정보·영업비밀의 불필요한 공개가 있는지 검토한다.

### 4.8.4 사람의 감독은 다음 작업을 실제 계정으로 시험한다.

1) 담당자가 불확실한 결과와 근거를 찾고 판단을 보류할 수 있는지 확인한다.
2) 결과를 거절·수정하고 그 이유와 영향받는 후속 처리를 기록한다.
3) 자동 처리를 중지하거나 수동 업무로 전환하고, 대리 담당자에게 필요한 정보·권한이 전달되는지 확인한다.
4) 변경·정정이 고객에게 반영되는지, 권한 없는 사람은 같은 조작을 할 수 없는지 확인한다.
5) 대응에 필요한 시간·정보가 부족하면 감독이 구현된 것으로 판정하지 않고 작업량·화면·권한·사용 범위의 보완을 요청한다.

### 4.8.5 고영향으로 판정된 시스템은 [F10](../forms/AIDU-AIP-08-01-F10.md)에 연결된 책무·게시·보관 증거를 확인한다. 감독자 성명·연락처는 지정 기록과 실제 게시본을 비교한다. 고영향 및 안전성 의무의 적용·세부 제출은 AIP-04-01과 AIP-08-01 4.13·4.15의 판단을 따른다.

## 4.9 배포·인계·복구 준비

### 4.9.1 [배포·변경·인계 F05](../forms/AIDU-AIP-08-01-F05.md)에 배포 버전 묶음, 영향 범위·고객, 시험 결과·잔여 리스크 수용·영향평가, 미해결 항목·제한, 고지·감독, 실행자·시점·복구 계획을 연결한다. 기술책임자의 승인은 해당 버전·범위에 대해 확인한다.

### 4.9.2 운영 담당자는 배포 전에 실행 환경·권한·키·외부 전송·기록·삭제·경보 설정을 확인한다. 시험 환경의 설정이 운영 환경과 다른 항목은 별도로 대조한다. 데이터 변환이나 외부 전송처럼 되돌릴 수 없는 효과는 코드 복원으로 해결되는 부분과 구분한다.

### 4.9.3 배포 범위·순서·중단 조건을 승인 계획에 따라 정하고 허용된 시험 요청으로 정상 처리·오류 처리·고지·로그·삭제 예약을 확인한다. 예상과 다른 동작이나 필수 보호 실패가 있으면 해당 기능의 확산을 막고 복구 또는 제한을 요청한다.

### 4.9.4 복구 계획에는 다음을 포함한다.

1) 이전 안정 코드·프롬프트·모델·설정의 이용 가능 여부와 복원 방법
2) 데이터 구조·상태의 호환성, 진행 중 요청·재시도·중복 처리의 정리
3) 복구해도 되돌릴 수 없는 전송·오판·고객 결정과 별도의 정정·통지
4) 외부 모델의 이전 버전 복원이 불가능한 경우 사용 제한·대체 모델·수동 처리 등의 검증된 대안
5) 복원 후 핵심 기능·보호·삭제 상태의 확인과 재개 승인

### 4.9.5 인계에서는 목적·허용 범위·알려진 한계, 이상 판단, 감독·연락·대리, 복구·삭제·고객 정정 방법을 운영 담당자가 실제로 찾고 수행할 수 있는지 확인한다. 배포 완료와 인계 확인을 F05에 남긴다.

## 4.10 운영 모니터링·로그·월별 검토

### 4.10.1 [운영·사건 F06](../forms/AIDU-AIP-08-01-F06.md)과 [측정 계획](../forms/AIDU-AIP-09-01-F01.md)에 지표·수집 방법·주기·기준선·임계값·담당·경보 수신자·대응·보유를 연결한다. 서비스 운영을 감시하는 주기와 월별 결과 검토, 연간 AIMS 종합 평가를 구분한다.

### 4.10.2 운영 중 점검은 다음 경로로 수행한다.

| 관찰 대상 | 확인 자료 | 이상 발견 시 연결 |
| --- | --- | --- |
| 오류·지연·중단·용량 | 요청 결과·오류 유형·지연 분포·자원·외부 API 상태 | 제한·복구·사건 조사 |
| 성능·판정 변화 | 허용된 표본·정정·불만·회귀 시험·집단별 결과 | 리스크·영향 재평가·변경 검증 |
| 입력·분포 변화 | 언어·형식·주제·길이·누락·거절 등의 변화 | 실제 성능 저하 여부 확인·사용 범위 검토 |
| 정보 보호·접근 | 승인 권한·전송 필드·오류 로그·키 사용·경보 | 전송·접근 차단·증거 보존 |
| 고지·감독·권리 행사 | 표시·게시·개입·대리·이의제기 처리 | 정정·업무 인계·교육·고객 안내 |
| 삭제·공급자 조건 | 만료 작업·사본·정책/모델 변경·지원 종료 | 재평가·삭제 재실행·전환 계획 |

### 4.10.3 추적 로그는 필요한 요청 식별자·처리 상태·모델/설정 버전·시각·오류 유형·사람 개입·관리 변경을 중심으로 구성한다. 입력·출력 원문은 목적·권한·기간이 승인된 경우에 한해 최소 범위로 수집한다. URL·헤더·스택 추적·진단 첨부에도 식별정보·비밀키가 남는지 확인한다.

### 4.10.4 경보의 생성뿐 아니라 수신·담당 연결·기록·조치가 동작하는지 시험한다. 감시 자료가 누락되거나 수집이 중단되면 정상으로 판정하지 않고 감시 실패의 원인·영향과 임시 확인 방법을 기록한다.

### 4.10.5 월별 검토에서는 기준 대비 변화, 중대 실패·정정·불만, 공급자·목적 변화, 미완료 조치·만료 데이터, 재평가 필요성을 정리한다. 중대한 피해나 필수 통제 실패는 월별 검토일까지 기다리지 않고 즉시 보호 절차로 연결한다.

## 4.11 변경·지속적 학습·재평가

### 4.11.1 변경 요청에는 전후 버전·목적·입력·출력·권한·공급자·데이터 조건의 차이를 적고 영향을 받는 요구·시험·리스크·영향·법적 판정·고지·교육을 표시한다. 영향이 없다고 판단한 범위에도 이유를 남긴다.

### 4.11.2 회귀 시험은 기존에 실패했거나 보호에 중요한 사례, 변경한 기능, 공통 의존성·고객 연동을 우선 포함한다. 재사용한 자료와 새로운 최종 판단 자료를 구분하고 승인 기준을 충족한 후 F05로 변경·배포를 승인받는다.

### 4.11.3 공급자 변경이 예고되지 않았으면 사용 시각·확인 가능한 모델 식별·관찰된 차이·영향을 기록한다. 안전한 범위에서 회귀 시험하고 제한·중지·대체를 검토한다. 공급자 변경을 회사의 자체 학습으로 기록하지 않는다.

### 4.11.4 지속적 학습을 실제 사용하는 경우에만 다음을 추가한다.

1) 업데이트 입력·주기·대상·허용 변화·데이터 사용권·품질을 정의한다.
2) 이전 안정 모델과 후보를 구분하고 독립 평가·필수 보호·집단별 결과를 확인한다.
3) 승인된 조건을 충족한 업데이트만 운영에 반영하며 실패·미확인은 보류한다.
4) 기준선·대표 테스트 갱신 시 과거 비교 가능성과 누출 여부를 확인한다.
5) 자동 중지·안정 버전 복원과 데이터·권한 추적이 실제로 동작하는지 확인한다.

### 4.11.5 재평가는 단순 성능 조정과 구분한다. 목적·요구·사용자·기본권 영향·법적 분류·AI 사용의 타당성이 달라졌는지 검토하여 계속 운영, 조건 변경, 개시/설계 복귀, 대체 또는 종료의 결정을 F05에 연결한다.

## 4.12 이상·사건의 초기 대응과 재개

### 4.12.1 발견자는 인지 시각·증상·대상 시스템·확인 가능한 범위를 운영 담당자와 기술책임자에게 즉시 알린다. 급박한 피해에는 승인된 비상 조치 범위에서 해당 기능·전송·계정·작업을 중지·격리한다. 전체 시스템을 일괄 파괴하거나 필요한 증거를 지우는 방식으로 대응하지 않는다.

### 4.12.2 접수자는 F06에 알려진 사실과 가설을 구분한다. 최소한의 요청·버전·설정·변경 이력으로 영향받은 고객·데이터·출력을 추적하고 증거의 접근권한과 보존 근거를 정한다. 원문이 필요할 때에는 승인된 제한 위치에서 최소 범위로 보관한다.

### 4.12.3 대응 책임자는 확산 차단·피해 정정·서비스 복구를 구분하여 작업을 배정한다. 영업 등 지정 담당자는 요구사항 대장의 수신자·조건·기한에 따라 승인된 내용으로 통지하고 확인된 사실·미확인 범위·후속 안내를 남긴다. 모든 사건에 동일한 법정 시간 제한을 임의로 적용하지 않는다.

### 4.12.4 운영 재개 전에는 원인·영향 범위, 필수 보호·재시험, 잔여 리스크, 데이터 무결성·삭제 상태, 고지·고객 정정·남은 의무를 확인하여 기술책임자에게 재개 결정을 요청한다. 복구 이후에는 [시정조치 기록](../forms/AIDU-AIP-10-01-F02.md)에 원인·유사 시스템·재발 방지·효과성 확인을 연결한다.

## 4.13 이의제기 결과의 기술적 정정

### 4.13.1 영업 담당자가 확인한 [이의제기 기록 F07](../forms/AIDU-AIP-08-01-F07.md)을 바탕으로 권한 있는 담당자가 대상 입력·결과·평가 기준·모델/설정 버전을 찾는다. 삭제된 자료가 있으면 없는 사실과 재검토의 한계를 기록하고 근거 없는 결과 복원을 하지 않는다.

### 4.13.2 적격한 사람이 원래 기준·추가 자료·AI 한계·잠재 오류를 검토한다. 같은 모델 재실행 결과만으로 이의를 기각하지 않는다. 오류가 공통 원인인지 확인하고 같은 문항·모델·고객·기간에 대한 재검토 범위를 정한다.

### 4.13.3 정정할 때에는 변경 전후 결과·이유·권한자·시각과 고객에게 전달한 버전을 연결한다. 회사의 기술적 정정과 고객의 성적·징계 등 최종 결정 처리를 구분하여 확인한다. 다른 고객의 데이터 노출 없이 당사자가 이해할 수 있는 설명·후속 경로를 제공한다.

## 4.14 보유 만료·삭제·백업 복구 확인

근거 절차: [정보 및 기록관리절차서](../procedure/AIDU-AIP-07-03.md) 4.5, AIP-08-01 4.4·4.12.

### 4.14.1 데이터 수집·이전 전에 [보유·폐기 관리표](../forms/AIDU-AIP-07-03-F04.md)에서 목적·기산 사건·기간·근거·저장/복제 범위·방법을 확인한다. Edu Score의 개인 학습 정보는 평가 종료 후 1개월 조건을 적용하고, 평가 종료 시점과 월 단위 만료 계산·예외 처리는 서비스별 명세에서 확인한다. 임의로 일률 30일로 바꾸거나 일반 관리 기록의 3년·5년 보유기간을 원문에 적용하지 않는다.

### 4.14.2 삭제 작업은 다음 순서로 수행한다.

1) 만료 대상 ID·기간·범위를 추출하고 조사·분쟁 등 근거 있는 삭제 보류 대상이 있는지 확인한다.
2) 재처리·재수집 작업이 대상을 다시 생성하지 않도록 관련 예약·큐·재시도를 확인한다.
3) 원본·파생정보·첨부·가명 연결정보·검색 인덱스·벡터·캐시·로그·백업·공급자 사본 중 해당하는 위치별로 삭제·반환·만료 작업을 실행한다.
4) 실행 결과·실패·재시도와 각 사본의 완료 여부를 대조한다. 숨김·비활성화·접근 차단을 삭제 완료로 표시하지 않는다.
5) 조회·검색·재처리·복구 관점에서 잔존 여부를 확인하고 남아 있는 사본은 위치·근거·해결 기한·보호 조치를 기록한다.
6) 삭제 증거에는 대상 범위·개수·실행/검증 시각·방법·담당·공급자 확인을 남기되 삭제한 개인정보를 다시 복사하지 않는다.

### 4.14.3 백업은 사본 목록·보유기간·삭제 방식·복구 시 재삭제 방법이 승인 조건을 충족하는지 수집 전에 확인한다. 선택 삭제가 어려운 구성은 만료·분리 보관 등 대안을 검토받고 기한을 충족할 수 없으면 설계를 보완한다. 백업에 남았다는 사실을 숨기거나 접근 차단만으로 삭제 완료를 선언하지 않는다.

### 4.14.4 복구 시험에서는 서비스 연결 전에 삭제 대상이 다시 활성화되지 않도록 삭제 상태를 재적용하고 조회·검색·재처리 경로를 확인한다. 삭제 상태를 관리하는 자료도 개인과 연결될 수 있으므로 최소 식별·접근·보유 기준을 정한다.

### 4.14.5 만료 대상은 월별로 대조하되 만료일이 그보다 빠르면 자동 만료 또는 수시 작업으로 기한을 지킨다. 실패·충돌은 즉시 기술책임자에게 보고하고 보완·재검증 및 시정조치에 연결한다. 장기 보관할 증거는 필요한 비식별 요약·설계·검증·승인 기록으로 분리한다.

## 4.15 서비스 종료와 자원 회수

### 4.15.1 [종료 F08](../forms/AIDU-AIP-08-01-F08.md)에 종료 기능·고객·일정·전환 방법·미처리 이의·법정/계약 의무·데이터·자원을 정리한다. 고객 고지·반환·삭제의 순서를 확인하고 필요한 검토·승인을 받는다.

### 4.15.2 담당자는 신규 요청·예약 작업·재시도·외부 연동을 정리한 뒤 승인된 반환·삭제·이전을 수행한다. 계정·키·권한·라이선스·외부 연결·정기 호출을 회수하고, 남겨야 할 기록을 별도 보유 위치와 책임자에게 인계한다.

### 4.15.3 종료 확인에는 고객 전환·외부 사본·백업·법정 보관·미해결 권리 행사 담당을 포함한다. 시스템 목록·리스크·SoA·운영 상태를 갱신하고 종료 후 문의·구제·보존 해제·삭제의 책임을 남긴다. 이용이 끝났다는 사실만으로 미완료 이의제기나 필요한 증거를 일괄 폐기하지 않는다.

### 5.2 실제 코드·설정·데이터·로그·시험 결과·고지문·감독자 정보는 승인된 저장소에서 별도 관리한다. 이 지침의 방법·질문·지표는 실행 완료나 준수 판정의 증거가 아니다. 실제 승인·시행·회람은 정보 및 기록관리절차에 따른다.
