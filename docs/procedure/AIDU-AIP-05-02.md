# 1 목적

매뉴얼 5.3의 기능상 역할을 실제 업무와 담당자에게 배정하고, 겸임·직무 분리·대리 수행·보고 및 조직 변경을 관리한다.

# 2 적용범위

대표이사, 기술책임자, 인공지능안전관리자 및 AI 관련 업무를 수행하는 임직원·외부 수행자에게 적용한다. 실제 성명·지정일·권한·대리자는 별도 역할 지정서에 기록한다.

# 3 책임과 권한

- 대표이사는 주요 역할과 위임 범위를 승인하고 이해충돌의 상향 보고를 처리한다.
- 기술책임자는 AIMS 적합성과 성능 보고를 총괄하고 업무분장·자원·역량을 검토한다.
- 인공지능안전관리자는 인공지능안전 및 AIMS 운영 실무를 분장받은 담당자·부서의 역할이다. 특정 부서나 한 사람만을 의미하지 않는다. 총괄 조정담당과 각 실무 담당을 지정하여 관리한다.
- 총무팀은 역할 지정·통지·인계 기록과 최신 연락망을 관리한다.

# 4 업무절차

## 4.1 역할 요구의 식별

인공지능안전관리자는 적용범위와 프로세스별로 수행·검토·승인·보고·대리 역할, 요구 역량, 필요한 접근권한 및 이해충돌 가능성을 정한다. 신규 업무·조직 개편·퇴직·장기 부재 시 변경안을 작성한다. 역할이 비어 있거나 적격자가 없으면 기술책임자가 대리자·교육·외부 지원 또는 업무 보류를 결정한다.

## 4.2 부서별 업무분장 기준

현재 직무 체계에서는 다음 기준으로 배정안을 작성한다. 실제 임명과 대리 수행은 F01로 승인하며, 조직 개편 시 동일 기능을 맡는 부서·직무로 배정을 갱신한다.

| 기능상의 역할·업무 | 배정 기준 | 책임의 범위 |
| --- | --- | --- |
| 대표이사 | CEO | 방침·목표·주요 자원·적용범위 승인, 경영검토 |
| 기술책임자 | CTO | AIMS 책임, 기술·보안·AI 의사결정, 개발·검증·승인, 경영진 보고 |
| 경영·기획 및 자원 조정 | COO/CFO | 예산·인력 조정, 경영지원 부서의 실행 지원 |
| 인공지능안전관리자 중 안전·영향평가 및 실무 조정 | Privacy & AI Safety Engineer | 영향평가, 리스크 취합, 개인정보·안전 검토, 분장된 업무의 진행 취합 |
| 인공지능안전관리자 중 문서·교육 운영 | 총무팀 | 문서·기록 통제, 교육 운영·역량 증거, 연락망·배포 |
| 인공지능안전관리자 중 공급자 계약 | 회계팀 | 계약·보관·학습 활용 등 조건 확인과 계약 기록 |
| 인공지능안전관리자 중 고객 의사소통 | 영업팀 | 고객 요구, 승인된 정보 제공, 불만·이의제기 접수 |
| 개발·데이터·AI 구현 | 개발/AI팀 | 설계·구현·개발 검토, 데이터 품질·가명처리, 외부 모델 통합 |
| 검증·운영·보호 | 운영팀 | 배포 검증, 인프라·보안·안전 검토, 모니터링·복구 |
| 내부심사 | 적격성·독립성을 충족한 인원 | 회계팀·DevOps Engineer를 기본 풀로 하되 건별 이해충돌 검토 후 배정 |

각 실무 담당은 소관 통제를 이행하고 기술책임자에게 보고한다. 총괄 조정담당에게 업무를 취합하더라도 기술책임자의 AIMS 책임이나 각 담당자의 실행 책임을 이전하지 않는다.

## 4.3 지정·통지·권한 부여

1. 총무팀은 후보자의 업무량·역량·겸임·이해충돌을 확인하고 F01·F02에 배정안을 작성한다.
2. 기술책임자는 누락과 중복, 검토·승인 권한 및 대리 범위를 검토하고 대표이사가 주요 역할·위임을 승인한다. 세부 작업 배정은 승인된 위임 범위에서 업무 책임자가 정한다.
3. 총무팀은 지정 대상자와 관련 인원에게 책임·권한·보고 경로·효력 발생일을 전달하고 수령·이해를 확인한다.
4. 권한 담당자는 지정 범위에 맞는 계정·자료 접근을 부여한다. 직무 지정이 시스템 접근권한을 자동 부여하는 것은 아니며 실제 부여·회수는 자원관리 절차와 연결한다.

## 4.4 겸임과 직무 분리

개발·검증·승인은 기술책임자가 수행하되 개발에는 개발/AI팀 전원, 검증에는 운영팀 전원이 참여하도록 한다. 참여 범위, 검토 결과와 이견을 구분하여 보유하고 기술책임자는 미해결 사항·잔여 리스크를 확인하여 승인한다. 대리 참여가 필요한 경우 사유·동등 역량·검증 범위를 사전에 지정한다.

개발자와 검증자가 겹치는 경우 다른 적격자의 검토 또는 외부 검토를 추가한다. 대표이사는 기술책임자와 관련된 중대한 이해충돌·미해결 이견에 추가 검증을 지시한다. 필수 요구사항 미충족은 승인으로 면제하지 않는다.

내부심사에서는 자신이 수행·검토·승인한 업무를 심사하지 않는다. 회계팀의 공급자 계약, DevOps Engineer의 인프라·배포는 각각 다른 적격자에게 배정한다. 교차 배정만으로 역량과 독립성을 충족한다고 보지 않으며 AIDU-AIP-09-02에서 건별로 확인한다.

## 4.5 우려사항 보고 및 대리·인계

누구나 안전·공정성·정보 보호·검증 누락 우려를 인공지능안전관리자 또는 기술책임자에게 보고할 수 있다. 해당 책임자와 관련된 사안은 대표이사에게 직접 보고할 수 있다. 선의의 보고에 불이익을 주지 않으며 제보자와 내용의 접근을 제한한다. 접수 후 영향이 진행 중이면 AIDU-AIP-08-01에 따라 긴급 중지·보호 조치를 수행한다.

보고 접수자는 사건·부적합·개선 여부를 구분하여 해당 절차로 이관하고 접수자에게 처리 상태를 회신한다. 총무팀은 담당자 변경·부재 전에 미완료 건, 승인 권한, 자료·계정·키, 대리 기간을 F03으로 인계하고 종료 시 권한을 회수한다. 기술책임자는 분기별 및 조직 변경 시 역할 공백·권한 과다·겸임 위험을 검토한다.

## 4.6 수명주기별 책무와 독립 검토

시스템 책임자는 F02에서 요구·데이터·모델·통합·검증·배포·고객 사용·모니터링·사건·폐기별 수행자, 리스크 책임자, 검토자, 승인자와 협의·통보 대상을 정한다. 회사·공급자·고객의 복수 역할과 법적 의무 주체도 연결하고 외주 작업의 책임 공백을 확인한다. 위험의 인수와 사업 승인 권한, 중지·재개 권한은 서로 구분한다.

고영향 AI에는 실제 사람인 관리·감독자와 대리를 지정한다. 총무팀은 역량·업무량·시간·접근·중지 권한을 확인하고 08-01의 공개 성명·연락처와 일치시킨다. 인공지능안전관리자의 업무를 분담하는 부서 체계와 해당 시스템의 감독자 지정을 혼동하지 않는다. 퇴직·부재 시 감독 공백이 생기면 해당 자동 판단을 제한하고 인계 후 재개한다.

윤리·권리 충돌, 중대한 위험, 평가자 자신의 설계에 관한 이견에는 직접 구현·사업 성과에 이해관계가 없는 적격자의 의견을 추가한다. 내부 인원이 부족하면 필요한 범위의 외부 분야·법률·윤리 전문가를 활용한다. 대표이사가 자원을 결정하되 전문 판단을 근거 없이 대체하지 않는다. 형식적 교차 서명만으로 독립성이나 역량을 충족했다고 처리하지 않는다.

우려사항 보고 경로는 내부 직원·외주 수행자에게 업무 시작 전에 알리고 선의의 보고자를 보호한다. 접수자는 2영업일 이내 안내를 목표로 담당·기한·보호를 정하며 급박한 위험은 즉시 처리한다. 보고자에게 가능한 범위의 결과·후속 경로를 알리고 미해결 이견을 삭제하지 않는다. 분기 역할 검토에는 미처리 보고·인계 누락·감독 과부하도 포함한다.
