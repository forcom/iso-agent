# 1 목적

매뉴얼 6.1.4 및 8.4에 따라 AI 시스템의 개발·제공·사용이 개인·집단·사회에 미치는 잠재적 긍정·부정 영향을 평가하고 설계·운영·리스크 처리 및 이해관계자 정보 제공에 반영한다.

# 2 적용범위

신규·기존 AI 시스템의 전체 수명주기와 의도된 사용·예측 가능한 오용·외부 서비스 의존성에 적용한다. 피영향자와 평가 결과는 시스템별 산출물로 작성하며 특정 서비스의 평가 결론을 공통 절차에 고정하지 않는다.

# 3 책임과 권한

- 인공지능안전관리자 중 영향평가 담당자는 평가를 주관하고 개인정보·안전 담당 및 관련 부서의 의견을 취합한다.
- 기술책임자는 기술적 전제, 조치 및 잔여 영향·사용 제한을 검토·승인한다.
- 개발·운영 담당자는 시스템·데이터·시험 자료를 제공하고, 영업 담당자는 고객·사용자·피영향자의 의견을 수집한다.
- 대표이사는 중대한 미해결 영향에 필요한 자원과 사업 범위를 결정한다. 수용 불가 리스크를 면제하지 않는다.

# 4 업무절차

## 4.1 개시·범위·평가 계획

인공지능안전관리자는 신규 시스템의 설계·제공 전, 연 1회 이상, 목적·피영향자·자동화 수준·데이터·모델·고객 사용 환경 변경 및 사건·중대한 불만 발생 시 영향평가를 실시한다. F01에 대상·버전·국가·기간·수명주기·직간접 영향 범위, 평가자·분야 전문가·참여자·자료·방법·일정·재평가 계기를 정하고 기술책임자가 승인한다. 개시 때 알 수 없던 영향은 설계·시험·운영 증거가 확보될 때 보완한다.

AIMS 범위의 시스템 영향평가는 매뉴얼과 본 절차에 따른 회사의 필수 활동이다. 인공지능기본법 제35조의 고영향 AI 영향평가와 제30조제3항의 사전 검증·인증은 법률상 노력의무로 구분한다. 고영향으로 판정된 시스템의 영향평가에는 시행령 제28조의 일곱 항목을 포함하여 하나의 평가로 대응 관계를 유지한다. 자체 평가 또는 외부 전문 평가를 선택하되 전문성·이해충돌·자료 접근성을 확인한다.

## 4.2 피영향자·권리·사용 시나리오 식별

시스템 책임자는 직접 사용자뿐 아니라 출력의 판단 대상, 데이터 주체, 고객 조직, 직원·외주 인력, 지역사회·사회 전체를 식별한다. 사용하지 않거나 데이터에 충분히 나타나지 않는 집단, 장애·연령·언어·디지털 접근·경제 여건으로 불리할 수 있는 집단을 포함한다. 법 제3조제5항의 인공지능취약계층 해당성·특성을 확인하여 평가에 반영한다. 민감한 속성을 평가한다는 이유로 필요한 근거 없이 새 개인정보를 수집하지 않는다.

각 시나리오에 목적·결정·사용 행태, 입력에서 권리·기회·안전의 변화까지의 경로, 예상 이익과 피해·수혜자·부담자, 합리적으로 예견되는 오용·과신·불용, 자동화 수준과 인간 개입, 반복·누적·장기·간접 영향을 기록한다. Edu Score는 성적·기회에 대한 오류와 낙인, AI 작성 확률 오탐, 표현·언어 차이, 평가 기준과 학습 목표의 타당성, 교원의 과신, 이의제기 부담을 확인한다. 다른 서비스는 해당 분야 전문가와 시나리오를 새로 작성한다.

## 4.3 윤리·사회 쟁점과 대안 검토

평가자는 다음 14개 주제를 모두 검토하여 F04에 적용성·근거·질문·발견·추가 검토를 남긴다. 모든 주제가 같은 비중을 갖는다고 가정하지 않으며 관련 없음도 대상·사용 맥락에 근거해야 한다.

| 검토 주제 | 판단할 질문과 확인 증거 |
| --- | --- |
| 책무성 | 누가 결정·실행·감독·구제하는가, 데이터·설계·승인·사용 결과를 추적할 수 있는가 |
| 공정성·차별 방지 | 어떤 집단에 어떤 오류·부담이 집중되는가, 동일 대우와 필요에 따른 형평이 충돌하는가, 선택 지표의 한계는 무엇인가 |
| 투명성·설명가능성 | 누가 AI 사용을 알아야 하는가, 결과의 주요 요인·한계·개입 방법을 이해할 수 있는가, 설명이 실제 동작과 일치하는가 |
| 전문적 책임 | 주장하는 능력과 측정 대상의 과학적 타당성이 있는가, 잘못된 상관관계·알려진 결함·전문성 한계를 검토했는가 |
| 인간적 가치 | 존엄·자율성·학습·복지에 어떤 이익과 제약이 생기는가, 가장 영향을 받는 사람에게도 선택이 정당한가 |
| 개인정보 | 목적·최소 수집·보유·공유·재식별·권리 행사와 거절 시 대안은 어떤가 |
| 안전성·보안성 | 오작동·적대 입력·오염·정보 유출·중단이 누구에게 피해를 주며 예방·복구가 가능한가 |
| 인간의 통제 | 개입할 사람에게 역량·시간·정보·권한이 있는가, 중지·정정·통제권 인계가 실제 동작하는가 |
| 지역사회 참여·개발 | 직접 고객 외에 영향을 받는 공동체가 참여할 통로와 공익·접근성 영향 검토가 있는가 |
| 인간 중심 설계 | 실제 작업 환경과 사용자 능력·필요를 반영했는가, 접근성·사용성 시험과 반복 개선이 있는가 |
| 법치주의 존중 | 권리·의무 판단의 적법성, 이의제기·사람의 재검토·구제·외부 절차 접근이 보장되는가 |
| 국제 행동 규범 존중 | 관할별 법령과 인권·정당한 이해관계·지식재산권의 충돌을 어떻게 해결하는가 |
| 환경적 지속가능성 | 모델·호출량·인프라의 에너지·자원 소비, 공급망·폐기 영향과 더 적은 자원을 쓰는 대안을 검토했는가 |
| 노동 관행 | 업무 대체·숙련 상실·감시·차별·과로, 외주 라벨링·유해 콘텐츠 검토 노동자의 부담과 재교육·협의가 필요한가 |

윤리 판단은 문제 인식 → 사실·피영향자 의견 수집 → 대안 비교 → 이유 있는 결정·실행 → 결과 검토 순서로 수행한다. 비AI·수동 처리, AI의 보조적 사용, 자동화·데이터·대상 축소, 제공 중단을 포함해 실행 가능한 대안을 비교한다. 개인정보와 공정성 측정, 설명과 보안·영업비밀, 정확도와 접근성 같은 충돌에는 영향을 받는 권리·가치·선택 근거·한계를 명시한다. 이익의 합계로 특정 집단의 중대한 피해를 숨기지 않는다.

기술책임자는 분야·기술·보호 관점의 검토를 모으고 미해결 권리 충돌·금지 사용·이해충돌은 대표이사에게 상신한다. 별도 상설 위원회가 없더라도 쟁점에 필요한 외부 전문가·독립 검토자를 확보한다. 법적 금지나 회사의 수용 불가 조건은 예외 승인하지 않는다.

## 4.4 이해관계자 협의와 영향의 분석

인공지능안전관리자는 결과가 확정되기 전에 영향받는 집단과 사용자·분야 전문가의 의견을 받는다. 영업팀은 고객과 피영향자 접점을 마련하고 총무팀은 직원 의견을 수집한다. 설문·면담·접근성·사용성 시험·대표자 협의를 사안에 맞게 선택하고 F04에 선정 근거·대표성·설명 자료·질문·의견·반영·미반영 이유·후속 회신을 남긴다. 고객 담당자 의견만으로 학습자 등 피영향자 전체를 대표했다고 보지 않는다. 직접 참여가 불가능하면 대리 의견·선행 연구의 한계와 보완 기한을 기록한다.

평가자는 F02에 규모·심각도·발생 가능성·기간·회복·누적·집단 간 분배, 정량·정성 지표와 산출 방법·자료·불확실성을 기록한다. 가능성을 알 수 없으면 억지 점수를 만들지 않고 가능한 피해·필요 정보·예방 조치를 정한다. 회사 리스크 평가와 연계하되 사람의 기본권 영향을 회사 손실만으로 대체하지 않는다.

고영향 AI의 평가에서는 다음 일곱 항목의 위치를 명시한다: ① 취약계층 특성을 반영한 개인·집단 식별 ② 기본권 유형 ③ 사회·경제적 영향의 내용·범위 ④ 사용 행태 ⑤ 정량·정성 지표와 결과 산출 방식 ⑥ 예방·완화·손실 복구 ⑦ 개선 이행계획. 사업자가 자체 또는 제3자 평가를 선택한 근거도 남긴다.

## 4.5 조치·승인·전달·사후 확인

인공지능안전관리자는 부정적 영향을 06-01의 리스크에 연결하고 예방·완화·사람의 재검토·정정·피해 복구 조치별 책임·자원·기한·검증·지표를 정한다. 긍정적 영향의 실현과 불공정한 이익 배분의 개선도 목표로 연결한다. 설계 수정·사용 제한·중단이 필요하면 08-01 단계 전환 조건에 반영한다.

기술책임자는 평가의 충분성, 협의·이견 처리, 잔여 영향, 조치의 검증 결과를 확인하여 승인·보완·보류를 결정한다. 조치 계획만 있고 배포 전 필수 보호가 확인되지 않으면 제공을 승인하지 않는다. 대표이사가 결정한 윤리 쟁점도 같은 기록에 연결한다.

F03에 고객·사용자·피영향자·공급자·당국별 제공 목적·범위·시점·보호 근거를 정하고 이해할 수 있는 요약과 구제 경로를 제공한다. 공개하지 않는 원자료와 공개할 주요 위험·한계를 구분한다. 운영 중 월별 모니터링·불만·새로운 사용·사고를 통해 평가의 가정과 조치 효과를 확인한다. 새 영향·대표성 부족·조치 실패가 발견되면 관련 단계를 다시 수행하고 이전 제공본의 갱신·통지를 추적한다.
