# 1 목적

매뉴얼 7.4~7.5에 따라 내부·외부 의사소통과 문서화된 정보의 작성·승인·배포·접근·변경·보유·폐기를 관리한다.

# 2 적용범위

AIMS의 매뉴얼·절차서·지침서, 방침·계획·평가 등 산출물, 실행 증거인 기록, 외부 출처 정보 및 의사소통에 적용한다. 매체·도구와 관계없이 동일하게 적용한다.

# 3 책임과 권한

- 대표이사는 매뉴얼·절차서·지침서 및 AI 방침을 승인한다. 개별 산출물·기록의 승인은 해당 절차에 정한 권한을 따른다.
- 기술책임자는 문서의 요구사항 충족·정합성을 검토하고 공식 저장소·보호·보유 기준을 승인한다.
- 총무팀은 문서관리 담당으로서 문서대장·유효본·배포·회수·보유·폐기와 공통 의사소통 계획을 관리한다.
- 작성자·업무 책임자는 내용의 정확성·근거·변경 필요성·보유 조건을 결정한다. 영업팀은 고객 의사소통, 회계팀은 공급자 의사소통을 담당한다.
- 운영팀은 권한·백업·복구·삭제를 실행하고 인공지능안전관리자는 보호 의무·공개 범위·보유 기준을 검토한다.

# 4 업무절차

## 4.1 정보 식별과 저장소 지정

총무팀은 문서체계와 각 절차의 요구 기록을 F01에 등록한다. 업무 책임자는 정보의 목적·소유자·작성자·검토자·승인자·매체·저장 위치·검색 키·접근 등급을 정한다. 접근 등급은 공개, 사내, 제한으로 구분하고 개인정보·비밀키·보안 상세·제보자 정보는 제한으로 관리한다.

기술책임자는 권한 통제·버전 이력·승인 추적·검색·내보내기·백업·삭제 가능성을 확인하여 공식 저장소를 지정한다. 현재 사용하는 협업 도구라는 이유만으로 공식 저장소로 간주하지 않는다. 대화·이메일에서 내려진 업무 결정도 필요한 경우 담당자가 공식 기록으로 연결하고 승인자를 확인한다.

문서번호는 문서체계를 따른다. 양식은 `절차서번호-F일련번호`로 식별하며, 각 절차의 5항에서 필수 필드를 정하고 [문서양식 목차](../forms/README.md)에 연결된 개별 Markdown 파일을 빈 양식 원본으로 관리한다. 담당자는 원본을 복사하여 별도 산출물·기록을 작성한다. 표·문서·시스템 화면 등 다른 매체를 사용할 때에도 필수 필드와 검토·승인 이력을 유지한다. 양식을 다른 절차와 통합할 때는 충족하는 양식 ID와 필드의 대응 관계를 남긴다. 양식의 필수 항목을 변경하면 근거 절차와의 일치 여부를 함께 검토한다.

작성된 산출물·기록에는 `양식ID-연도-일련번호` 또는 중복 없는 시스템 ID를 부여하고 양식 버전·시스템·업무·연결 기록을 표시한다. 방침·목표·평가 결과·SoA·임명·서명·회의록 등 실제 결과는 규정 문서 본문에 넣지 않는다. 작성되지 않은 항목은 미확정 또는 해당 없음과 사유를 구분하며 승인·시행일을 소급하여 만들지 않는다.

## 4.2 작성·검토·승인

1. 작성자는 제목·ID·작성일·작성자·버전·상태·적용범위와 내용을 작성하고 근거·관련 문서를 연결한다. 읽을 수 있는 형식과 필요한 사용 언어를 선택한다.
2. 업무 책임자와 기술책임자는 요구사항 충족, 책임·입출력·양식, 다른 문서와의 일치, 정보 보호 및 실행 가능성을 검토한다. 이견과 반영 결과를 남긴다.
3. 권한자가 승인하고 총무팀은 승인자·실제 승인일·효력 발생일을 등록한다. 초안·검토 중·승인·폐기를 구분하고 초안은 시행본으로 배포하지 않는다.
4. 절차별 실제 산출물은 해당 절차의 승인자를 따른다. 전자 승인도 승인 대상 버전·승인자·시각·결정이 식별되고 임의 변경되지 않아야 한다.

## 4.3 배포·이용·변경

총무팀은 승인본의 사용 위치·대상·시행일을 공지하고 필요한 교육을 요청한다. 사용자는 작업 전에 유효한 버전을 확인한다. 외부 배포본은 수신자·버전·범위·재배포 조건을 기록한다.

업무 책임자는 법령·계약·방침·역할·프로세스 변경과 사건·심사 결과에 따라 개정을 요청한다. 총무팀은 변경 사유·대상·영향·이력을 F02로 관리하고 최초 작성과 같은 검토·승인을 거친다. 중대한 AIMS 변경은 AIDU-AIP-06-03에 연결한다.

시행 시 이전본을 사용 위치에서 회수하거나 폐기본으로 표시하여 참조용 보관과 구분한다. 보유 기록의 오류를 정정할 때 원본·정정자·시각·사유·정정 내용을 추적하고 이전 증거를 덮어쓰지 않는다. 권한·버전·가독성·검색 가능성은 분기별 및 저장소 변경 시 점검한다.

## 4.4 외부 출처 정보 관리

업무 책임자는 표준·법령·고객 요구·공급자 사양·이용 조건 등 필요한 외부 정보를 F03에 등록한다. 공식 출처·발행자·버전·효력일·확인일·적용 범위·담당자·갱신 방법을 기록한다. 법률·시행령·유효한 고시·행정 가이드라인·표준의 성격을 구분하고 공포일·시행일·경과조치·과거 버전을 함께 식별한다. 공식 게시 가이드라인에 고시 번호가 공란·예시로 남아 있으면 그 내용만으로 법정 기한이나 새로운 의무를 확정하지 않는다.

담당자는 변경 통지를 수신하고 분기별 및 계약·모델·서비스 변경 전에 최신성과 적용성을 확인한다. 변경 내용을 조직상황·준수평가·리스크·설계·계약·교육에 전달한다. 적용 여부가 미확정인 사항은 해결 책임자와 기한을 정하고, 필수 요구 충족을 확인할 수 없는 관련 배포·데이터 처리는 보류한다.

## 4.5 보유·보호·복구·폐기

업무 책임자는 정보 생성 전에 F04에 보유 목적·기산점·기간·근거·폐기 방법을 정하고 인공지능안전관리자가 법령·계약·개인정보 조건을 검토하며 기술책임자가 승인한다. 다음은 회사의 기본 관리 기준이며 특정 정보에 적용되는 의무와 제한을 먼저 확인한다.

| 정보 유형 | 기본 보유 기준 |
| --- | --- |
| 규정 문서·방침·적용범위·유효 계획·SoA | 유효 기간 동안 유지하고 대체·폐기 후 3년간 이력 보유 |
| 시스템 명세·리스크·영향평가·검증·승인 | 해당 버전의 사용·지원 기간 동안 유지하고 대체 또는 사용·지원 종료 중 늦은 날부터 3년간 보유 |
| 교육·심사·경영검토·측정·시정조치 등 관리 증거 | 업무 종결일부터 3년간 보유하되 개인 식별정보의 필요성·보유 근거 별도 검토 |
| 고영향 AI의 법 제34조 책무 이행 근거 | 시행령 제27조제2항에 따라 5년 보관. 회사 기준으로 개별 이행 기록은 해당 조치 완료일부터 5년, 계속 유효한 정책·체계·설명 방안은 유효 기간 유지 후 대체·종료일부터 5년. 적용 고시·다른 법령이 별도 기산점을 정하면 그 기준을 확인·반영 |
| 고객·사용자 개인정보 및 개인과 연결되는 입력·출력·로그·백업 | 시스템별 승인된 처리 목적·법적 근거·계약에 따른 기간 적용. 위 관리 증거의 3년·5년 기준으로 일괄 연장하지 않음 |

같은 기록에 여러 보유 의무가 적용되면 대상 정보·법적 근거·기산점·기간을 대조한다. 고영향 책무의 이행 증거에는 방안·역할·게시·검증·조치·갱신 자료 등 필요한 범위를 지정하며 모든 이용자의 입력·출력 원문을 5년간 보관하는 것으로 해석하지 않는다. 위 기산점 중 법령에 명시되지 않은 부분은 회사의 보유 기준이다.

Edu Score의 개인 학습 정보는 회사 설정인 평가 종료 후 1개월 보유·삭제 조건을 데이터 관리표와 삭제 작업에 반영한다. 다른 서비스는 도입 전에 별도 기준을 결정한다. 증거를 더 오래 유지해야 하면 원본 개인정보를 남기는 대신 필요한 최소한의 비식별 통계·검증 요약을 생성하고 재식별 가능성을 확인한다. 별도 법적 보존 의무가 확인되면 근거·범위·기간·접근 제한·목적 외 사용 금지를 기록하며 근거 없는 일괄 보유 연장을 하지 않는다.

운영팀은 승인된 권한·암호화·백업·복구 기준을 적용하고 복구 시험으로 가독성과 무결성을 확인한다. 백업·복제본·캐시·로그·외부 제공분도 보유 기준에 포함하며, 승인된 기한을 지킬 수 있는 삭제·만료 방식을 데이터 수집 전에 확보한다. 삭제 대상이 복구로 다시 활성화되지 않도록 삭제 상태를 재적용한다.

총무팀과 업무 책임자는 월별로 만료 대상을 확인하고 운영 담당자가 승인된 일정에 따라 삭제·반환한다. 기한이 월별 확인일보다 앞서면 자동 만료 또는 별도 작업으로 기한을 지킨다. 삭제 대상 ID·범위·방법·실행·검증·공급자 확인을 기록하고 개인정보 원문을 폐기 증거에 복사하지 않는다. 보유·삭제 충돌이나 이행 실패는 즉시 기술책임자에게 보고하고 AIDU-AIP-10-01로 처리한다.

## 4.6 의사소통 계획·실행·확인

총무팀은 연간 계획 수립 시 및 수신자·의무 변경 시 F05에 내용, 시기·발생 조건, 대상, 방법, 담당·승인, 기밀 범위와 응답·수령 확인 방법을 정한다. 다음 항목은 반드시 판단한다.

| 내용 | 대상·시기 결정 기준 |
| --- | --- |
| 방침·목표·역할·업무 변경 | 영향을 받는 내부 수행자에게 시행 전, 외부 수행 의무가 있으면 해당 공급자에게 적용 전 |
| 사용 목적·한계·사람의 감독·이의제기 | 고객·사용자가 도입·사용을 결정하기 전 및 중요한 조건 변경 전 |
| 리스크·영향평가·처리 정보 | 조치 참여자, 피영향자의 권리 행사 또는 법령·계약상 제공 의무에 필요한 수신자에게 해당 결정·기한 전 |
| 사건·장애·잘못된 출력·데이터 침해 | AIDU-AIP-08-01에 따라 즉시 내부 보고하고 외부 통지는 요구사항 대장의 기한·조건 적용 |
| 성과·심사·시정·경영검토 | 해당 절차에서 정한 주기·결정 시점에 책임자와 경영진에게 전달 |

리스크·영향·윤리 판단의 의사소통에는 전달뿐 아니라 질문·의견·대안 협의, 미반영 이유와 재검토를 포함한다. 고영향 AI의 게시 정보와 관리·감독자 성명·연락처, AI 사전 고지·표시, 이의제기·구제 경로는 08-01-F09·F10과 연결하여 변경 즉시 최신성을 확인한다. 개인정보·영업비밀 보호 범위와 의무 공개 범위를 구분하고 제한 근거를 기록한다.

담당자는 승인된 내용·채널로 전달하고 발송·수령·질문·미도달·후속 조치를 기록한다. 통상 업무 정보는 담당 책임자가 승인하고, 중대한 사건·대외 입장·분쟁은 기술책임자와 대표이사에게 보고하여 권한에 따라 승인한다. 긴급 통지 의무의 기한을 넘기지 않도록 부재 시 대리 권한을 미리 정한다.

정보 제공 요청은 수신자·목적·의무·기밀·개인정보 범위를 검토하여 제공·부분 제공·거절과 사유를 기록하고 회신한다. 보호가 필요한 내용은 최소화하되 사용자 보호·권리 행사에 필요한 한계·피해 정보를 누락하지 않는다.

## 4.7 의사결정 증거와 수명주기 추적

시스템 책임자는 목적·요구사항 ID → 데이터/모델/코드/설정 버전 → 평가·협의·대안 선택 → 시험·검토 → 승인·배포 → 운영·개입·사건 → 정정·폐기의 연결을 유지한다. 외부 모델은 제공받은 버전·식별정보·자료 날짜와 재현 한계를 남긴다. 증거가 없는 사항은 미확인으로 표시하고 초안·참고 사례·시뮬레이션을 실제 실행 기록으로 등록하지 않는다.

총무팀과 운영팀은 분기 점검에서 표본 기록의 검색·권한·무결성·가독성·복구·외부 제공본·법정 보유기간을 확인한다. 오류 정정은 원본과 변경 사유·담당·시각을 보유하며 정정으로 의사결정 당시 증거를 덮어쓰지 않는다. 조사·분쟁 보존이 필요하면 권한 있는 결정의 근거·범위·담당·해제 조건을 남기고 개인정보는 필요한 범위로 제한한다. 보존 해제 후 원래의 삭제 기준을 적용한다.
