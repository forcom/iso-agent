# 1 목적

매뉴얼 8.1의 운용 기획·관리와 6.3의 변경 기획을 실행하고 리스크 처리·영향평가·의사소통을 서비스의 도입부터 종료까지 연결한다. 단계별 입력·판단·승인·기록을 정하여 기획된 기준대로 업무가 수행되도록 한다.

# 2 적용범위

회사가 개발·제공·도입·사용하는 모든 AI 시스템과 관련 데이터·모델·외부 서비스·고객 관계에 적용한다. 외부 모델을 사용하는 서비스와 향후 자체 학습·파인튜닝 또는 다른 분야의 서비스에도 적용하며 실제 기능·처리 조건·설정은 시스템별 명세에 작성한다.

세부 작업 방법은 AIDU-AIG-08-01 인공지능경영활동관리규정 및 AIDU-AIG-08-02 시스템 수명 주기 및 데이터 관리지침서에서 정한다. 해당 지침의 마련 여부와 관계없이 본 절차의 평가·검증·승인·정보 보호 요건을 충족해야 한다.

# 3 책임과 권한

- 기술책임자는 운용 기준·설계·검증·배포·중대한 변경·운영 재개를 승인한다. 필수 요구사항이나 리스크 수용 기준 미충족을 승인으로 면제하지 않는다.
- 대표이사는 주요 자원·사업 범위·이해충돌·중대한 대외 의사결정을 담당한다.
- 개발/AI팀은 요구사항·설계·구현·데이터 처리에 참여하고 운영팀은 검증·보호·배포·모니터링·복구에 참여한다. 기술책임자에게 개발·검증·승인이 집중되는 구조를 AIDU-AIP-05-02의 참여·이견·추가 검토로 보완한다.
- 인공지능안전관리자는 리스크·영향·준수·정보 보호와 조치 이행을 확인한다. 회계팀은 공급자 계약, 영업팀은 고객 요구·정보 제공·이의제기, 총무팀은 기록·교육 관리를 분담한다.
- 시스템별 책임자는 단계별 기록·연결 관계·미완료 사항을 관리한다. 업무 담당자는 급박한 피해를 막기 위해 승인된 비상 절차에 따라 사용·전송·배포를 중지하고 즉시 기술책임자에게 보고할 수 있다.

# 4 업무절차

## 4.1 도입 요청·시스템 정의·운용 기획

시스템 책임자는 고객 확약·실데이터 처리 전에 F01에 해결할 문제·성공 기준, 비AI 대안, 의도된 목적·사용자·피영향자·국가·예견 가능한 오용, 수명주기·외부 의존성을 작성한다. 04-01의 범위·법령 적용 판정, 06-01의 리스크 기준과 06-02의 영향·윤리 검토를 개시한다. 기술책임자는 타당성·자료·전문성·자원을 검토하여 착수·보완·보류를 결정한다.

시스템 명세에서는 모델과 전체 시스템을 구분한다. 입력·데이터 수집·지식/검색·학습·추론·예측·권고·결정·행동·피드백의 흐름을 그리고, 모델·프롬프트·도구·규칙 기반 처리·사용자 화면·API·인프라·사람·외부 고객의 경계를 표시한다. 자동화된 처리와 사람이 정한 목표·범위 안에서의 자율적 판단·행동을 구분하여 인간의 개입 시점과 허용 권한을 정한다. 모델이 같은 서비스도 통합 방식·목적·행동 권한이 다르면 별도 평가한다.

요구사항에는 기능·성능뿐 아니라 견고성(입력·환경 변화에 대한 허용 성능), 신뢰성(정한 조건·기간의 기능 유지), 복원력(실패 후 복구), 유지보수성(결함 수정·새 요구에 대한 변경 가능성), 제어가능성(개입·정정·중지), 설명가능성·투명성·공정성·개인정보·보안·사용성·접근성·환경·종료를 포함한다. 각 요구의 출처·측정 방법·합격 기준·제외 근거·책임자를 정한다. 법적 역할과 ISO의 공급자·생산자·통합자·고객·사용자·주체 역할을 매핑하고 법적 고영향·생성형·안전성 대상 여부는 04-01-F05에 연결한다.

책임 있는 개발·사용 목표, 처리 통제·SoA, 영향 저감 조치, 단계별 산출물·승인·재평가·일정·비용을 수명주기 계획으로 통합한다. 현재 자체 학습이 없더라도 자체 학습·미세조정·지속적 학습을 새로 도입하면 해당 단계와 통제를 활성화한다.

## 4.2 단계별 전환 기준

단계 산출물은 독립 문서로 작성하거나 연결된 관리 시스템에서 유지할 수 있다. 각 단계의 기준을 충족했음을 확인한 후 다음 단계로 전환한다.

| 단계 | 전환 전에 확인할 내용 | 승인·확인 |
| --- | --- | --- |
| 도입·요구 정의 | 목적·역할·요구사항·대상·평가 범위·자원·미확정 사항 처리 | 기술책임자, 사업·범위·예산은 해당 승인권자 |
| 설계·개발 착수 | 데이터·공급자 조건, 설계·검증 계획, 리스크 처리·영향 저감 요구 | 기술책임자; 개발/AI팀 참여 |
| 검증 착수 | 버전 확정, 구현·검토 증거, 시험 데이터·환경·판정 기준 | 기술책임자; 운영팀 참여 |
| 배포·사용 개시 | 요구사항 검증, 통제 효과성·잔여 리스크 수용, 영향평가, 사용자 정보·운영·복구 준비 | 기술책임자 |
| 변경·운영 재개 | 변경 영향·재검증·복구·통지, 미해결 사항과 수용 기준 충족 | 기술책임자 |
| 종료 | 고객·공급자 통지, 데이터·권리 행사·서비스 전환·자원 회수 완료 조건 | 기술책임자; 계약 종료는 계약 권한자 |

단계 보류 사유·보완 책임·기한을 기록한다. 실데이터 없는 시험과 제한된 검증은 허용 범위·보호 조치를 별도로 승인하되 이를 서비스 배포 승인으로 간주하지 않는다.

## 4.3 설계·개발 및 기술 문서화

개발/AI팀은 기능·데이터 흐름, 모델·프롬프트·설정·코드·의존성, 외부 API별 역할, 입력 제한, 출력 표시, 실패·거절·대체 처리, 사람의 확인·정정·중단 권한을 설계한다. 모델의 알려진 한계·공급자가 제공하지 않는 정보·회사 검증의 범위를 구분한다.

중요 권리나 기회에 영향을 주는 결과는 사용자가 한계와 근거를 이해하고 적격한 사람이 검토·변경·이의제기 처리를 할 수 있도록 설계한다. AI 작성 확률 등 불확실한 추정치를 확정 사실처럼 표시하지 않으며 불이익 결정에 사용될 가능성을 요구사항·영향평가·시험에 반영한다.

개발에는 개발/AI팀 전원이 참여하고 의견·설계 결정·미해결 사항을 기록한다. 버전별로 요구사항에서 구현·시험·승인까지 추적한다. 자체 학습·파인튜닝을 도입하면 학습 목적, 데이터 사용 권한·분할·오염 방지, 실험 조건·모델 계보·재현 한계와 평가 계획을 추가한다. 현재 자체 학습을 하지 않는다는 이유로 도입 이후의 검토를 생략하지 않는다.

설계 담당자는 자동 판단이 사람의 권리·기회·안전에 미치는 경로별로 출력 거절·보류·수동 대체·권한 제한을 정한다. 사용자가 검토할 시간·근거·불확실성 표시와 실제 수정·중지 권한이 없는 상태를 인간의 감독으로 인정하지 않는다. 모델이 생성한 이유 설명이 실제 판단 근거인지 검증하고 확인할 수 없는 내부 과정을 사실처럼 설명하지 않는다.

자체 학습·미세조정 시 실험별 목적·알고리즘·초매개변수·훈련 코드·데이터 계보·환경·연산량·모델 산출물·비교 결과를 기록한다. 외부 모델은 회사가 확인할 수 있는 모델·API·배포 버전과 공급자 정보의 공백을 기록한다. 재현 불가능한 부분은 반복 실험·변동 범위·대체 증거로 관리한다.

## 4.4 데이터 수명주기 관리

Data Engineer 등 지정된 데이터 담당자는 F02에 데이터별 출처·취득 권한·처리 목적·품질 기준·변환·전송·보유·삭제를 정한다. 인공지능안전관리자는 개인정보·민감성·권리·목적 적합성을, 기술책임자는 사용 준비 상태를 검토한다.

1. 수집·취득 전 허용된 목적·계약·사용 권한·출처와 필요한 최소 범위를 확인한다. 시험·분석·학습 등 용도가 달라지면 새로운 목적에 대한 근거를 확인한다.
2. 완전성·정확성·대표성·최신성·라벨 신뢰도·편향을 용도별 기준으로 점검한다. 결측·오류·중복·오염·부적절한 내용의 처리와 제외 근거를 기록한다.
3. 전처리·가명처리·분할·변환의 버전·규칙·수행·검증을 추적한다. 외부 전송 전 직접 식별자와 자유서술 내 식별 가능 정보를 점검하고 가명 연결정보는 분리·제한한다. 가명처리를 익명화로 간주하지 않는다.
4. 실제 외부 전송 필드·목적지·모델·지역·공급자 조건이 승인 범위와 일치하는지 시험한다. 보관 금지와 학습 활용 금지를 별개로 검증하고 공급자 설정·계약·예외를 확인한다.
5. 데이터 품질·출처·분포·사용 조건 변경을 모니터링한다. 부적합 데이터는 격리하고 이미 생성된 출력·평가·고객 결과에 미친 영향을 추적한다.
6. 입력·출력·파생정보·로그·캐시·백업·공급자 사본의 보유·삭제를 AIDU-AIP-07-03과 연결하고 삭제·반환 결과를 검증한다.

Edu Score를 등록·변경할 때는 성인 대상, 개인 학습 정보의 외부 API 전송 전 가명처리, 공급자 보관·학습 활용 금지, 평가 종료 후 1개월 보유·삭제 및 저장 위치 등 회사가 정한 조건을 시스템별 명세·계약·검증 기준에 반영한다. 다른 서비스의 조건은 그 서비스의 요구사항 분석으로 결정한다. 회사 요구조건이 공급자에서 실제 지원되는지는 별도로 확인하며 증거 없이 충족으로 처리하지 않는다.

훈련 데이터, 후보·설정을 선택하는 검증 데이터, 최종 성능을 판단하는 테스트 데이터와 운영 데이터를 구분한다. 프롬프트·검색·규칙을 조정하는 데이터도 개발용으로 표시한다. 최종 테스트는 조정에 사용한 데이터와 분리하고 중복·유사 문항·정답 노출·오염을 점검한다. 데이터가 부족하여 교차검증 등을 쓰면 방법·한계·최종 평가의 독립성 확보 방식을 사전 승인한다. 운영 데이터를 재학습·평가에 재사용하려면 목적·권한·보유·분할을 다시 검토한다.

라벨·기준 답안은 객관적 진실로 가정하지 않는다. 작성자 전문성·기준·복수 평가자의 일치·불일치 해결·수정 이력·표본 검사 결과를 보유한다. 데이터별 모집단·표집 방법·시점·분포·누락 집단·편향·변환 계보·품질 기준과 수용 여부를 기록한다. 데이터 증강·합성·결측 대체는 원자료와 구분하고 원래의 편향 확대·평가 누출을 검사한다. 공급자 학습 데이터의 상세를 얻지 못하면 알려진 개요·출처·불확실성과 회사가 추가 검증할 범위를 남긴다.

## 4.5 공급자 및 고객 책임 관리

회계팀은 계약 전과 갱신 전 F04에 공급 범위·책임·조건을 수집하고 기술책임자와 인공지능안전관리자가 다음 항목을 검토한다.

- 공급자의 기능·성능·한계·지원·보안·준수 증거와 회사가 검증해야 할 범위
- 데이터 처리 목적·보관·학습 활용·위치·재위탁·접근·삭제·반환과 변경 통지
- 사고 통지·조사 협력·서비스 중단·모델 변경·지원 종료·전환·계약 종료
- 책임 경계, 필요한 기술 문서·검증 근거·감사 또는 확인 권한

검토 결과는 승인·조건부 승인·보류로 구분한다. 조건부 승인은 사소한 보완의 범위·기한과 허용 작업을 정한 경우에 한하며, 필수 데이터 처리 조건·리스크 수용 기준 미충족 상태의 실데이터 사용·배포를 허용하지 않는다. 기술 승인 후 권한자가 계약하고 실제 계정·플랜·설정·하위 제공 조건을 다시 확인한다.

핵심 모델·인프라·데이터 처리 공급자는 분기별, 그 밖의 공급자는 연 1회 및 변경·사고 발생 시 재평가한다. 계약상 주장과 실제 운용 증거를 구분하며 미충족 시 전송·사용 제한, 시정 요구, 대체·종료를 결정한다. 대체 공급자로의 전환도 검증·승인을 거친다.

영업팀은 고객과 도입 목적, 허용·금지 사용, 입력·평가기준 제공, 이용자 고지·권리 행사, 사람의 판단·정정, 데이터 처리·보유, 사고·이의제기 연락과 종료 책임을 확인한다. 기술책임자는 수행 가능성을 확인하고 계약 권한자가 약정을 승인한다. 회사·공급자·고객 간 책임을 분담하더라도 회사가 수행해야 하는 검증과 보호 의무를 누락하지 않는다.

공급자 검토에는 성능·안전·데이터 출처 및 권한·취약점·모델 변경·지원 종료에 관한 정보 제공, 고객에 제공할 설명·표시의 유지, 관련 노동·환경 영향 자료와 대체 가능성을 포함한다. 외부 개발사업자에게 고영향 책무 이행에 필요한 자료를 요청하고 확보·미확보 범위와 보완 조치를 기록한다. 해외 사업자에게 국내대리인 의무가 적용되면 지정 연락처·업무 범위도 확인한다. 국내 회사 자체에 해외 사업자용 국내대리인 의무를 자동 부과하지 않는다.

기술책임자는 공급자의 인증·선언·시험과 회사 통합 시스템의 검증 범위를 구분한다. 시행령 제27조제3항의 이행 간주를 적용하려면 선행 사업자의 법 제34조제1항제1~3호 조치, 본래 목적·용도의 현저한 변경 등 중대한 기능 변경 부재, 회사가 이어받은 조치의 범위를 항목별로 증명한다. 사람의 관리·감독과 문서화 의무까지 면제하지 않는다. 범용 API를 평가 서비스로 통합하는 경우에도 조건을 개별 확인한다. 다른 법률상 조치의 간주는 같은 조 제5항·별표 1의 정확한 대응 조건을 확인한 경우에만 적용한다.

## 4.6 검증 및 타당성 확인

기술책임자는 시험 전에 F03의 요구사항별 시험 방법·데이터·환경·표본·반복 조건·합격 기준을 승인한다. 운영팀 전원이 검증에 참여하고 구현자와 검증자가 겹치면 AIDU-AIP-05-02에 따른 추가 검토를 적용한다.

시험에는 정상·경계·오용·예외 입력, 출력의 정확성·일관성·유용성, 중요한 집단별 오류·편향, 보안·개인정보, 사람의 감독·정정·중지, 장애·복구·용량 및 공급자 연동 조건을 포함한다. 사용 목적별로 필요한 항목과 제외 사유를 정한다. 비결정적 출력은 반복 시험·분포·허용 변동을 정하고 평균만으로 중요한 실패를 숨기지 않는다.

교육 평가 기능에서는 평가 기준과 기준 답안·전문가 판단의 관계, 서술형·에세이의 타당성, 학습자 집단별 오류, AI 작성 확률의 오탐·미탐과 설명·이의제기 가능성을 검토한다. 신규 분야는 해당 사용 맥락과 분야 전문가의 판단을 검증 계획에 반영한다.

검증자는 실제 결과·실패·편차·증거·수정·재시험을 기록하고 의도된 사용에서 요구를 충족하는지 확인한다. 리스크 처리의 효과성과 영향 저감 조치도 확인하여 AIDU-AIP-06-01·06-02에 반환한다. 시험 후 결과에 맞춰 합격 기준을 낮추지 않는다. 기준 변경이 필요하면 근거·영향·승인을 남기고 해당 범위를 다시 검증한다.

확인(verification)은 명세대로 구현되었는지를, 타당성 확인(validation)은 실제 의도된 용도·환경에서 필요를 충족하는지를 구분하여 기록한다. 모델 단위 성능과 비AI 구성·고객 연동·사람의 업무를 포함한 종단 간 시험을 각각 수행한다. 대표성 있는 분리 테스트, 비교 기준선, 집단별 오류·오탐·미탐·보정 상태, 표본 크기·불확실성·재현 조건을 보고한다. 공정성 지표는 보호할 가치·오류 비용·집단별 표본에 따라 선택하고 서로 충돌하는 지표의 선택 이유를 남긴다.

분포 밖 입력, 시간 경과·환경 변화, 적대 입력·프롬프트 주입·데이터 오염·출력 유출, 공급자 장애·응답 변동, 사람의 과신·개입 지연·수동 인계를 시나리오로 시험한다. 분야 전문가가 측정 개념·기준 답안·예측과 결과 사이의 타당성을 검토한다. 내부 구조를 검증할 수 없는 외부 모델은 확인 범위·추가 시험·보호·허용 용도를 명시하며 미확인 성능을 보증하지 않는다. 권리·안전의 필수 보호를 입증하지 못하면 해당 사용을 보류한다.

## 4.7 배포·사용 승인 및 인계

시스템 책임자는 확정 버전, 검증 결과, SoA 구현·잔여 리스크 수용, 영향평가, 미해결 항목, 사용자 안내, 담당자 역량, 모니터링·중지·복구·삭제 준비를 F05로 취합한다. 기술책임자는 배포·보류·제한된 범위의 승인과 근거를 기록한다. 기준을 충족하지 못한 기능은 제외하고 해당 기능의 호출·사용도 차단한다.

운영 담당자는 승인된 버전·시간·대상에 배포하고 설정·권한·전송 조건·모니터링의 실제 동작을 확인한다. 예상과 다르면 배포를 중지하거나 승인된 복구 계획을 실행하고 결과를 보고한다. 개발·운영·고객 담당 간 인계에서 책임·연락·사용 한계·이상 판단·전환 방법을 확인한다.

법적 적용 판정, 사전 고지·결과물 표시·사람의 감독 시험(F09), 고영향 및 안전성 의무의 이행 상태(F10)를 배포 확인 항목으로 포함한다. 이용자 화면·LMS/API 연동·내보내기에서도 필요한 고지·표시가 전달되는지 확인한다. 고객이 수행할 고지·사람의 판단·구제는 책임 분담과 실제 수행 확인 방법을 확보한다. 도구·계약·표시의 이름만으로 보호가 구현되었다고 판정하지 않는다.

## 4.8 사용자 정보·투명성·설명·인간의 감독

영업팀과 시스템 책임자는 사용 전에 목적·AI 사용 사실·성능·한계·불확실성·금지 용도·입력 조건·사람의 판단·개인정보·정정·이의제기 경로를 제공하고 F09에 내용·대상·제공 위치·버전·검증 증거를 남긴다. 법적 고영향 비해당이어도 생성형 AI 고지·표시 의무를 별도로 판단한다.

| 구분 | 적용 조건 및 실행 기준 |
| --- | --- |
| AI 기반 운용 사전 고지 | 법 제31조제1항에 해당하는 고영향 또는 생성형 AI 제품·서비스는 사용 전 계약·설명서·약관, 화면·단말, 인식하기 쉬운 제공 장소 등 시행령 제23조제1항의 방식으로 고지한다. |
| 생성형 결과물 표시 | 법 제31조제2항 대상 결과물은 사람이 인식하거나 기계가 판독하는 방법으로 표시한다. 기계 판독 방식만 사용하면 생성형 AI로 생성되었다는 사실을 안내 문구·음성 등으로 1회 이상 함께 알린다. |
| 실제와 구분하기 어려운 가상 콘텐츠 | 법 제31조제3항의 음향·이미지·영상 등은 AI 생성 사실을 명확하게 인식할 수 있게 고지·표시한다. 예술·창작 표현도 감상·향유를 저해하지 않는 방식으로 이행하며 전면 면제로 보지 않는다. 이용자의 나이·신체·사회적 조건과 시각·청각·소프트웨어 접근을 고려한다. |
| 예외 검토 | 시행령 제23조제4항의 AI 활용이 명백한 경우, 사업자 내부 업무에만 사용하는 경우, 유효한 고시의 예외는 조항별·기능별로 범위·근거를 F09에 기록하고 기술책임자가 검토한다. B2B라는 이유나 외부 API를 쓴다는 이유만으로 제외하지 않는다. |

Edu Score의 생성형 피드백 등 실제 생성 기능과 일반 계산·규칙 기반 점수 출력을 구분하고 결과물별 표시 방법을 정한다. 영업팀은 LMS 등 고객 화면에 필요한 고지·표시가 전달되는 책임을 약정하고 실제 적용 증거를 확인한다. 기능·출력·표시 경로가 바뀌면 재검증한다.

설명은 사용자·피영향자·운영자·통합자·당국의 목적에 맞게 시스템 목적, 주요 판단 요인·기준, 데이터 개요, 검증된 성능·한계, 결과를 바꿀 수 있는 정보와 정정 방법을 제공한다. 고영향 AI는 법 제34조제1항제2호에 따라 최종 결과·주요 기준·학습용 데이터 개요 등에 대한 기술적으로 가능한 범위의 설명 방안을 수립·시행한다. 제공할 수 없는 내부 정보는 이유·공급자 요청·대체 설명을 남기며 영업비밀을 이유로 모든 설명을 생략하지 않는다. AI가 생성한 사후 설명을 실제 내부 추론의 증거로 단정하지 않는다.

시스템 책임자는 사람의 감독이 필요한 판단, 담당자의 역량·접근·시간·부재 대리, 출력의 수정·거절·정정·중지·수동 전환 권한을 지정한다. 운영팀은 비정상 상황과 과신을 포함한 실습으로 개입이 가능한지 시험한다. 중요한 불이익 결정에 불확실한 AI 작성 확률 등을 단독 확정 근거로 사용하지 못하도록 사용 범위·화면·계약·고객 교육을 연결한다. 사람의 개입 결과와 이유는 필요한 최소 범위로 추적한다.

시스템 책임자는 대상별 기술 문서·언어·형태·시기를 07-03 의사소통 계획에 등록한다. 권리·선택에 영향을 주는 변경은 적용 전에 알리고 긴급 보호 변경은 조치와 함께 알린다. 내부 AI 사용도 승인된 도구·목적·데이터·권한·감독을 적용하고 위반 사용은 제한·재평가한다.

## 4.9 운영 모니터링 및 계획된 변경

운영팀은 시스템별 승인된 주기·임계값으로 성능·출력 오류·편향·데이터 변화·보안·가용성·사용량·공급자 변경·삭제 이행을 모니터링한다. 시스템 책임자는 월별로 운영 결과와 고객 불만을 검토하고 AIDU-AIP-09-01의 성과평가에 제공한다. 급박한 이상은 월별 검토까지 기다리지 않는다.

시스템 책임자는 수명주기 단계별 이벤트 로그의 필요성과 항목·수집 시점·보호·보유·조회 권한을 정한다. 사용 중에는 요청·처리 결과 상태·모델 및 설정 버전·사람의 개입·오류·관리 변경을 추적할 수 있게 기록한다. 입력·출력 원문 수집은 목적·필요성·보유 근거가 있는 최소 범위로 제한하고 비밀키·불필요한 개인정보를 남기지 않는다. 운영팀은 로그 생성·누락·무결성·검색·삭제 상태도 확인한다.

모델·프롬프트·데이터·코드·판정 기준·API·공급자 설정·사용자·사용 목적의 변경은 F05로 요청한다. 기술책임자는 영향 범위를 판단하여 요구사항·리스크·영향평가·검증·통지·교육·복구 범위를 정한다. 목적·피영향자·데이터 조건·공급자 또는 평가 전제를 바꾸는 변경은 중대한 변경으로 처리한다. 제한된 변경도 영향 없음의 근거와 필요한 회귀 검증·승인을 남긴다.

변경 시행 전에 버전과 되돌릴 수 있는 범위·조건을 확인하고 시행 후 예상 효과·부작용을 검증한다. 외부 모델의 예고 없는 변경 등 의도하지 않은 변경은 영향을 평가하여 제한·중지·완화·재검증한다. AIMS 변경과 함께 진행하면 AIDU-AIP-06-03의 변경 ID를 연결하여 승인·완료 상태가 일치하게 관리한다.

## 4.10 이상·사건 및 비상 대응

발견자는 안전·권리 침해, 데이터 유출·무단 전송, 중대한 오판, 필수 통제 실패, 광범위한 장애를 발견하면 즉시 운영 담당자와 기술책임자에게 보고한다. 접수자는 F06에 발생·인지 시각, 영향 범위와 근거를 등록한다. 급박한 피해에는 사전 지정된 중지·격리·접근 제한·전송 차단·대체 업무를 실행하고 보고한다.

기술책임자는 인공지능안전관리자와 함께 진행 중인 피해·확산 가능성·영향 대상·중요 업무·외부 의무를 기준으로 긴급성을 판단하고 대응 책임자를 지정한다. 중대한 권리·안전·개인정보 피해, 필수 요구 위반 또는 광범위한 중단은 즉시 대표이사에게 보고한다. 증거는 필요한 최소 범위로 보호하여 보유한다.

대응 책임자는 영향 시스템·버전·데이터·고객·출력을 확인하고 피해 완화·정정·복구를 수행한다. 영업팀 등 지정 담당자는 요구사항 대장에 정한 대상·조건·법정 또는 계약 기한에 따라 고객·피영향자·관계기관에 통지하며 내용·시각·수신·추가 통지를 기록한다. 사실이 불완전하면 확인된 사실과 조사 중인 내용을 구분하고 기한 내 후속 보고를 계획한다.

재개 전 원인·영향 범위, 필수 보호 조치, 재검증·잔여 리스크, 데이터 무결성과 사용자 안내를 확인한다. 기술책임자는 근거에 따라 재개 또는 제한 유지를 승인한다. 사건은 AIDU-AIP-10-01의 원인·재발 방지·효과성 확인까지 연결하며 서비스 복구만으로 종결하지 않는다.

## 4.11 불만·이의제기·구제

영업팀은 고객·사용자·피영향자의 불만과 결과 정정 요청을 F07에 등록한다. 접수 후 2영업일 이내를 내부 접수 안내 목표로 하되 적용 법령·계약이 더 빠른 대응을 요구하면 그 기한을 따른다. 즉시 피해가 예상되면 사건 대응을 먼저 개시한다.

담당자는 요청자의 권한을 필요한 범위로 확인하고 시스템·결과·버전·요구사항·권리와 처리 기한을 파악한다. 결과에 대한 이의는 최초 판단을 그대로 반복하는 방식으로 처리하지 않고 적격한 사람이 기준·입력·AI 한계·추가 증거를 검토한다. 이해충돌이 있으면 다른 적격자에게 배정한다.

기술책임자는 오류·영향·정정 범위를 결정하고 고객의 최종 결정 책임과 회사의 기술적 정정 책임을 연결한다. 영업팀은 처리 결과·이유·정정·추가 제기 경로와 지연 시 사유·예정일을 알린다. 유사 결과의 일괄 재검토 필요성, 리스크·영향평가·시정조치 필요성을 판단하고 회신·완료를 추적한다.

## 4.12 종료 및 폐기

시스템 책임자는 종료 전에 F08에 사유·대상·일정·고객·공급자 통지, 대체 수단, 미처리 이의·의무, 데이터 반환·삭제·정당한 보유, 기록·자원·키 회수와 책임을 작성한다. 종료로 새로운 피해가 생기는지 평가하고 기술책임자가 승인한다.

담당자는 계약·법령에 맞춰 전환·고지·삭제·회수를 실행한다. 지원 종료 후에도 남는 권리 행사·보유 의무의 담당자를 지정한다. 모델·데이터·문서·운영 지식을 다음 책임자에게 인계하고 유지보수 불능·공급자 종속으로 복구할 수 없는 상태가 되는지 확인한다. 시스템 책임자는 외부 사본을 포함한 종료 증거를 확인하고 목록·위험·SoA·운영 상태를 갱신한다.

## 4.13 고영향 AI 책무의 이행 확인

04-01의 판정 결과가 고영향이면 인공지능안전관리자는 제공 전에 F10에 다음 대응과 이행 증거를 취합하고 기술책임자가 검토한다. 대표이사는 필요한 자원과 담당 역할을 확보한다.

| 법 제34조의 책무 | 실행·확인할 내용 | 연결 기록 |

영업팀과 문서관리 담당자는 시행령 제27조제1항에 따라 위험관리정책·조직체계 등 주요 내용, 설명 방안 주요 내용, 이용자 보호 방안, 해당 AI를 관리·감독하는 사람의 **성명 및 연락처**를 사무소·사업장·홈페이지 등에 게시한다. 기술책임자는 게시 내용·접근성·유효성을 검토하고 변경 시 갱신한다. 실제 이름과 연락처는 별도 게시 산출물에 기재하며 본 절차서의 고정 직제·인명으로 만들지 않는다. 제외할 영업비밀은 법정 정의에 해당하는 부분과 이유를 특정한다.

이행 간주를 주장하는 항목은 4.5의 조건·범위를 증거로 확인하고 나머지 의무는 회사가 이행한다. 법 제30조제3항의 사전 검증·인증 노력은 자체·외부 검증 및 이용 가능한 인증의 범위·필요성·자원·추진 여부를 검토하여 남긴다. ISO 인증 취득이 법 제34조 전체 의무의 면제나 특정 제품의 안전 보증이 되었다고 표시하지 않는다. 영향평가는 06-02와 연결한다. 미이행한 필수 의무가 있으면 제공·확대 승인을 보류한다.

## 4.14 지속적 검증과 재평가

운영팀은 승인된 지표·임계값에 따라 분포 밖 입력, 데이터·개념 변화, 집단별 오류, 설명·고지 실패, 사람 개입·정정, 공급자 성능·버전 변화, 권리 행사·자원 사용을 감시한다. 분포 변화가 곧 성능 저하라고 가정하지 않고 성능·영향 자료로 확인하되 중대한 피해 우려에는 예방 조치를 먼저 한다. 시스템 책임자는 월별 결과를 검토하고 리스크·영향평가의 재개 조건을 판단한다.

운영 중 지속적 학습을 사용하는 시스템은 업데이트 가능 범위·검증 주기·테스트 갱신·감시·자동 중지·안정 버전 복구를 사전에 승인받는다. 운영 데이터의 대표성과 테스트 독립성을 유지하고 업데이트로 달라진 모델·데이터·권한을 추적한다. 기준을 벗어난 학습 결과를 자동으로 서비스에 반영하지 않는다. 지속적 학습을 하지 않는 외부 API 서비스에도 공급자 변경·출력 변동에 대한 회귀 검증을 적용하되 회사의 재학습과 혼동하지 않는다.

재평가는 모델 조정에 한정하지 않는다. 목적·요구사항이 여전히 유효한지, AI 사용이 타당한지, 피영향자·관할·법적 분류·이익과 피해·수용 기준이 바뀌었는지 확인한다. 기술책임자는 계속 운영·조건 변경·개시/설계 단계 복귀·대체·종료를 결정하고 F05에 근거·후속 평가·승인을 남긴다. 종료 시 미해결 권리 행사와 데이터·모델·지식·공급자 사본의 처리도 4.12로 확인한다.

## 4.15 법 제32조 안전성 확보 및 관계기관 대응

04-01-F05에서 시행령 제24조의 세 기준과 회사의 의무 주체 해당성을 검토하여 법 제32조 적용 대상으로 판단한 시스템에는 다음 절차를 추가한다. 누적 학습 연산량만으로 적용을 확정하거나 외부 API 이용만으로 면제하지 않는다.

1. 기술책임자는 현재 유효한 고시의 연산량 산정 방식·개발 또는 변경 행위의 적용 조건·제출 방식과 기한을 원문으로 확인하여 F10에 등록한다. 공급자·개발 담당자는 연산량·구성·기술 수준·위험 평가 자료를 제공한다. 확인되지 않은 고시 번호·기한을 가이드라인의 공란이나 예시로 채우지 않는다. 미확정이면 담당·확인 기한을 정하고 관련 제공을 보류한다.
2. 인공지능안전관리자는 수명주기 전반의 위험 식별·평가·완화, 안전사고 모니터링·대응 책임·연락·중지·격리·복구·훈련을 06-01과 본 절차 4.9~4.10에 연결한다. 중대한 악용·확산·연쇄 위험과 외부 의존성도 포함한다.
3. 시스템 책임자는 안전성 조치의 결과·변경·시험·잔여 위험·미해결 사항을 작성하고 기술책임자가 검토, 대표이사가 대외 제출을 승인한다. 담당자는 법 제32조제2항에 따른 과학기술정보통신부장관 제출을 확인된 방식·기한으로 수행하고 제출본·접수·보완 요구·후속 결과를 보유한다.
4. 사건 발생 시 4.10의 보호·통지와 함께 적용 고시·다른 법령·계약의 보고 대상·발생 조건·기한을 확인한다. 모든 AI 사건에 동일한 법정 시간 제한이 있다고 가정하지 않는다. 보고와 서비스 복구 이후에도 원인·재발 방지·효과성을 검증한다.

법 제40조 등에 따른 관계기관의 자료 제출·조사·시정 요청이 접수되면 담당자는 발신 기관·법적 근거·요구 범위·기한을 확인하고 기술책임자와 대표이사에게 즉시 보고한다. 관련 증거를 보존하고 제출·설명·명령 이행·재발 방지의 담당을 지정한다. 보존 대상 개인정보는 근거·최소 범위·접근 제한·해제 조건을 따로 정한다. 실제 요청과 승인 없이 제출·확인·법적 판단을 완료한 기록을 만들지 않는다.
