# 1 목적

매뉴얼 9.3에 따라 대표이사가 AIMS의 지속적인 적절성·충족성·효과성을 검토하고 개선과 변경에 관한 의사결정을 내리도록 한다.

# 2 적용범위

전체 AIMS와 그 적용범위에 포함된 서비스·프로세스의 성과, 변경, 이해관계자 요구와 개선 기회에 적용한다.

# 3 책임과 권한

- 대표이사는 경영검토를 주관하고 종합 판단·개선·변경·자원 관련 결정을 승인한다.
- 기술책임자는 입력의 충분성·정확성·미해결 위험을 검토하고 후속 조치를 지휘한다.
- 인공지능안전관리자는 일정·입력·회의 또는 서면 검토·결과·후속 상태를 관리한다.
- 각 업무 책임자는 자신의 성과·변경·문제·개선안을 제출하고 지정된 결정을 실행한다. COO/CFO는 필요한 예산·인력과 사업 영향을 검토한다.

# 4 업무절차

## 4.1 계획 및 소집

인공지능안전관리자는 연 1회 이상 내부심사·성과·준수평가 결과를 포함하여 경영검토를 계획한다. 검토 대상 기간과 자료 기준일, 참석·자료 담당, 제출·검토 일정을 정하고 대표이사가 확정한다.

중대한 사건·반복 부적합·필수 의무 위반, 새로운 사업·사용 분야, 큰 조직·자원 변경으로 AIMS의 적절성·충족성·효과성 판단이 달라질 수 있으면 기술책임자가 수시 검토를 요청한다. 정기 검토를 기다리는 동안 필요한 보호·시정조치는 즉시 수행한다.

회의 또는 서면으로 수행할 수 있으나 대표이사가 입력을 검토하고 질문·판단·의사결정을 남겨야 한다. 단순 자료 전달이나 대표이사의 검토 없는 실무 회의는 경영검토로 간주하지 않는다.

## 4.2 입력 자료 작성·확인

인공지능안전관리자는 F01에 다음 입력과 근거·추세·미확정 사항·권고안을 취합하고 기술책임자가 누락 여부를 확인한다.

| 필수 입력 | 작성·확인 내용 |
| --- | --- |
| 이전 경영검토 조치 상태 | 완료·미완료·기한 경과, 효과·잔여 문제·추가 결정 필요 |
| 외부·내부 이슈 변경 | 사업·기술·공급자·조직·역량·자원·법령·환경 관련 변경과 AIMS 영향 |
| 이해관계자 니즈·기대 변경 | 고객·사용자·피영향자·규제·공급자 요구, 불만·이의제기·권리 보호 |
| AIMS 성능 정보: 부적합·시정조치 경향 | 발생·심각도·유사 사례·반복·종결·효과성·기한 초과 |
| AIMS 성능 정보: 모니터링·측정 경향 | 목표 달성·품질·안전·공정성·보호·운용·통제 효과·준수평가와 한계 |
| AIMS 성능 정보: 심사결과 경향 | 심사 범위·발견·반복·독립성·후속 상태·프로그램 효과 |
| 지속적 개선 기회 | 우선순위·기대 효과·자원·리스크·대안·결정 필요 사항 |

추가로 방침·목표의 적합성, 리스크·영향평가·SoA, 자원·역량·책임의 충분성 및 필요한 AIMS 변경을 입력에 연결한다. 실적이 없거나 비교 자료가 없으면 그 사실·이유·확보 계획을 남긴다. 자료 공백을 양호한 상태로 해석하지 않는다.

## 4.3 검토 및 의사결정

대표이사는 다음 판단을 기록하고 개선 기회와 AIMS 변경 필요성에 대해 채택·보완·보류·불필요 여부 및 근거를 결정한다.

1. 현재 사업·목적·이해관계자·리스크에 AIMS가 맞는지에 대한 적절성
2. 적용 요구사항, 필요한 통제·프로세스·인력·자원을 갖추었는지에 대한 충족성
3. 방침·목표와 계획된 결과를 달성하고 피해·부적합을 관리하는지에 대한 효과성

결정에는 담당자·기한·자원·완료 및 효과성 확인 방법·보고 시기를 지정한다. 방침·목표·범위·역할·프로세스·통제 변경이 필요하면 해당 절차와 변경계획으로 연결한다. 보류 사안에는 잠정 조치·추가 정보·재검토일을 정한다. 필수 의무와 수용 불가 리스크는 경영검토에서 면제하지 않는다.

## 4.4 결과 확정·전달 및 후속 조치

인공지능안전관리자는 실제 검토일·참석 또는 검토자·입력·질의·판단·결정·이견을 F02에 기록하고 기술책임자 검토 후 대표이사가 승인한다. 결정사항은 실행 책임자에게 전달하고 수령·이해를 확인한다.

담당자는 승인된 결정을 실행하고 증거를 제출한다. 인공지능안전관리자는 월별로 진행·기한 경과를 추적하고 기술책임자는 효과를 확인하여 대표이사에게 보고한다. 기한·범위·자원 변경은 원래 결정 권한자의 승인을 받고 이력을 남긴다. 다음 경영검토에서 이전 조치의 상태와 효과를 다시 확인한다.

## 4.5 리스크 관리 체계와 책임 있는 AI의 재검토

대표이사는 필수 입력과 함께 리스크 관리의 설계·통합·실행·평가·개선이 현재 규모와 사용 맥락에 맞는지 검토한다. 기술책임자는 가정·기준의 유효성, 복합·누적 위험, 수용 만료·불확실성, 외부 공급자 종속·역량, 윤리 대안·미해결 이견과 이해관계자 협의의 대표성을 보고한다. 자원 부족·성과 압박·자동화 과신이 보호 활동을 약화시키는지도 확인한다.

고영향 및 안전성 대상의 실제 책무·공개·보관·제출, 생성형 고지·표시, 법령 변화, 영향평가·사전 검증 노력과 결과를 검토한다. 새로운 의무·피영향자·기술 변화가 있으면 기존 방침·목표·기준·범위·사업 진행 조건의 변경을 결정한다. 중대한 피해와 법적 의무 미충족은 성능·매출 성과로 상쇄하지 않는다.

F02에는 유지·개선·재설계·축소·중단·대체, 사람·자원 확보, 추가 전문 검토, 공개·구제 등 결정과 근거를 남긴다. 실행 책임·일정·효과성 검증을 지정하고 다음 검토에서 실제 개선과 부작용을 확인한다. 경영검토 승인 자체를 시스템 배포 승인·잔여 위험 수용·법적 확인으로 대체하지 않는다.
